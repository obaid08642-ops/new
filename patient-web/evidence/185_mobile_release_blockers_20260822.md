# حواجز إصدار تطبيق الموبايل المثبتة — إحالة من مرحلة أمان الويب

**المصدر:** `../evidence/42_manual_verified_findings.tsv`، نتائج تدقيق يدوي مثبتة.  
**النطاق:** هذه العيوب في تطبيق React Native/Expo المرجعي، وليست تغييرات مقترحة أو منفذة داخل مستودع الويب.

| المعرّف | الأولوية | العيب المثبت | خطر الإصدار | شرط الإغلاق |
|---|---|---|---|---|
| MSEC-001 وMSEC-005 وMSEC-016 | P1 | الرجوع من التخزين الآمن إلى AsyncStorage لرموز الدخول أو حفظها فيه مباشرة | تعريض رموز الوصول/التحديث على جهاز مخترق أو عند فشل SecureStore | خدمة موحدة للتخزين الآمن تفشل بشكل آمن، تمسح المفاتيح القديمة، وتمنع أي fallback نصي. |
| MDATA-002 | P1 | تحويل فشل تحليل JSON بعد نجاح HTTP إلى كائن نجاح مصطنع | واجهات تتقدم استناداً إلى بيانات غير حقيقية أو انحراف عقد | خطأ عقدي Typed أو Result صريح وحالة واجهة فشل، بلا كائن نجاح بديل. |
| MLOG-007 وMLOG-012 | P1 | إعادة محاولات وإعادة تشغيل mutations بلا idempotency أو تأكيد حالة | حجوزات أو طلبات أو مدفوعات أو وصفات مكررة أو متأخرة | قصر الإعادة على الطرق idempotent، مفتاح Idempotency-Key من الخادم، مدة صلاحية وسياسة مورد وإظهار حالة معلقة. |
| MDATA-008 | P1 | تحويل mutation غير المتصل إلى استجابة نجاح وهمية | تقدم حالة المستخدم من دون تأكيد دائم من الخادم | نوع pending/failure مفصول ولا قيمة مجال مصطنعة. |
| MSEC-009 وMSEC-011 | P1 | حفظ طلبات غير متصلة كاملة مع headers وبيانات حساسة في AsyncStorage | بقاء PHI أو Authorization في تخزين غير مشفر | حذف Authorization، مخطط سماحي مصغّر، تخزين مشفر، TTL والتحقق قبل التشغيل. |
| MSEC-014 وMSEC-015 | P1 | كلمة مرور في route params وكلمة افتراضية متوقعة لتحويل الضيف | تسريب أو استيلاء محتمل على الحساب | معاملة مؤقتة محمية في الذاكرة أو رمز صادر من الباك إند؛ منع أي كلمة افتراضية. |
| MDATA-017 | P1 | اختراع جلسة ضيف وهوية ورمز محليين عند فشل إعادة المصادقة | تمثيل غير صادق لجلسة مريض وقد تظهر تدفقات غير مسموحة | حالة غير متصلة غير مصادق عليها صريحة بلا رمز أو مريض مصطنع. |

## عيوب P2 ذات صلة بالجودة والتكافؤ

يبقى MQA-006 (بوابة lint مكسورة) وMCON-021 (انحراف عقد دردشة الموبايل) وMUI-022 (زر إضافة عنوان خامل) عناصر منع جودة/وظيفة قبل الحكم الإنتاجي لتطبيق الموبايل. هذه العناصر لا تُحل بتغييرات ويب، ولا ينبغي ربط إصلاحات الويب بها أو الادعاء بأنها أغلقت.

> **الحكم المحدود:** ويب المريض يمكنه إغلاق مخاطر مستودعه الخاصة، لكن تطبيق الموبايل يظل **NO-GO مستقلاً** ما دامت عيوب P1 أعلاه بلا إصلاح واختبار. لا يغيّر هذا السجل الشفرة أو العقود أو بيانات Sandbox.
