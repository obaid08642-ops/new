# بوابة الأمن — دفعة واجهة Premium والتفاصيل

## النطاق والقرار

يغطي هذا التدقيق إعادة تصميم صفحات الدخول والقوائم والتفاصيل، ونظام الحركة، وطبقة metadata العامة. لا يغير أي عقد BFF أو سياسة cookie أو عملية API، ولا ينشئ بيانات مريض أو محتوى طبي بديلاً.

| المحور | الضابط المنفذ | الدليل |
|---|---|---|
| الجلسة والتوكن | لم تتغير cookies `httpOnly` أو استدعاءات BFF. نموذج الدخول يرسل الاعتماد إلى `/api/auth/login` فقط ولا يثبت حسابات Sandbox أو كلمات مرور في HTML. | اختبار `tests/login-form.test.tsx`. |
| BOLA/IDOR | صفحات الطلب والموعد والتشخيص تستخدم المعرّف المقيد وخدمة الخادم مع `401` للدخول، و`403/404` لإخفاء الوجود. | اختبارات SSR وSandbox للطلب والموعد. |
| العرض المسموح | تفاصيل الطلب تحجب العميل والعنوان والسعر؛ تفاصيل الموعد تحجب اسم المريض والهاتف والملاحظات والسعر؛ الفحص يحجب التقرير؛ الدواء العام يحجب السعر وبيانات المريض. | اختبارات SSR التفصيلية لكل صفحة. |
| التنقل | أضيف رابط رجوع واحد إلى القائمة الأم لكل صفحة تفاصيل، واختبر عدم ظهور روابط للتقارير أو الملفات أو محادثات غير موثقة. | اختبارات `orders` و`appointments` و`diagnostics` و`medicine-detail`. |
| الحركة | الحركة مقتصرة على `opacity` و`transform` وبمدد قصيرة، ولا تستخدم لتظاهر بتغير صحي أو إخفاء تحميل شبكة. | CSS موحد مع `prefers-reduced-motion`. |
| الاكتشاف | Open Graph/Twitter للصفحة الرئيسية العامة فقط؛ جميع المسارات الخاصة تحت `X-Robots-Tag`، والكتالوج المختلط يبقى `noindex`. | اختبارات metadata وrobots وتحقق HTTP. |
| BFF المتاح للمتصفح | بوابة `/api/patient/[...path]` تقبل قراءات `GET` للطلبات الموثقة المدرجة فقط؛ ترفض أي كتابة أو مورد غير مدرج قبل قراءة الجلسة أو تجديدها. | `lib/api/patient-allowlist.ts` واختبارات route الخاصة بالبوابة. |
| تعذر الخلفية | أي فشل اتصال من BFF يعاد كـ`503 upstream_unavailable` بلا استثناء غير معالج أو حمولة حساسة؛ لا تتحول المهلة إلى نجاح أو قائمة بديلة. | `lib/api/upstream.test.ts` و`app/[locale]/health/health-ssr.test.ts`. |

## نتائج التحقق

| التحقق | النتيجة |
|---|---|
| `pnpm check` | ناجح. |
| `pnpm test` | 53 ملفاً ناجحاً، 85 اختباراً ناجحاً؛ اختبارات Sandbox معزولة افتراضياً. |
| `pnpm build` | ناجح. |
| Sandbox: ملكية الطلب | نجح المالك، ورفض الحساب الآخر حسب العقد. |
| Sandbox: ملكية الموعد | نجح المالك، ورفض الحساب الآخر عند وجود مورد قابل للاختبار. |
| Sandbox: الانحدار المتسلسل | اجتازت دفعات الطلب والمواعيد والتشخيص والدواء والعائلة قبل أن يتعذر اتصال API أثناء دفعة العلامات الحيوية؛ لم تتحول المهلة إلى نجاح أو بيانات بديلة. |
| Sandbox: إعادة تحقق العلامات الحيوية | نجح التشغيل المنفرد في 20 أغسطس 2026: قرأ ملخص العلامات الحيوية الذاتي للمالك من دون كتابة أو طباعة قيم صحية، وأعاد `401` بلا جلسة؛ لا يثبت ذلك أي تشخيص أو إدخال أو عملية تغيير. |
| تحقق HTML العام | Open Graph/Twitter للصفحة العامة، و`noindex` للخاص والكتالوج المختلط. |
| التحقق اللاحق على فرع المراجعة | `pnpm check` و`pnpm build` ناجحان؛ `pnpm test` يسجل 55 ملف اختبار و94 اختباراً ناجحاً، مع عزل 23 اختبار Sandbox عن التشغيل المحلي المتزامن. |

## القيود المتعمدة

تظل تفاصيل الرعاية المنزلية، الوصفات، والمحادثات مقفلة إلى أن تسلم الخلفية عقود الملكية والـDTOs الموثقة. لا تعالج إعادة التصميم هذه الفجوات، ولا تضيف متابعة أو حجزاً أو إلغاءً أو إرسالاً أو رفعاً أو تشخيصاً أو توصية علاجية.

عولجت مهلة Sandbox السابقة بإعادة تحقق منفردة ناجحة بعد فترة تهدئة. تظل الواجهة قرائية فقط، ولا تحول هذه النتيجة عقد ملخص العلامات الحيوية إلى عقد إدخال أو تنبيه أو توصية علاجية.

## قرار البوابة

تجتاز دفعة الواجهة الحالية بوابة القراءة الآمنة والتصميم، وتبقى غير مؤهلة للنشر النهائي قبل إغلاق فجوات Backend وتحديد مسار GitHub المعتمد.
