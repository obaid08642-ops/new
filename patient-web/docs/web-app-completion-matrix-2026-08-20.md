# مصفوفة اكتمال Web App المريض — نبض بلس

## القرار التشغيلي

يُبنى الويب من ثلاث طبقات: **واجهة Next.js** للعرض والوصولية، و**BFF خادمي** يحمل جلسة المريض في cookies `httpOnly` ويتصل بـOpenAPI، و**Backend الإنتاجي** الذي يبقى المصدر الوحيد لبيانات المريض. لا توجد بيانات demo أو fallback ناجح أو تخزين متصفح للتوكنات. عند غياب عقد أو تفويض قابل للاختبار، تظهر الواجهة حالة غير متاح/فارغ/رفض حقيقية بدلاً من وظيفة ظاهرية.

| الرحلة | المسار | واجهة وUX | عقد البيانات الحالي | حالة الحماية والاختبار | القرار المتبقي |
|---|---|---|---|---|---|

## حواجز مشتركة لا يجوز تجاوزها

| الطبقة | الضابط الإلزامي |
|---|---|
| BFF | لا Bearer token في المتصفح، ولا استدعاء API من عميل الصفحة الخاصة؛ تستخدم الصفحة خادم Next فقط. |
| التفويض | كل route بمعرف مورد يحتاج تحقق ملكية backend، واختبار owner مقابل other عند توفر مورد. |
| العرض | allowlist للحقول المعروضة؛ لا IDs داخلية أو أسعار أو ملفات أو تقرير أو سجل طبي غير مثبت. |
| حالات UX | loading وempty وforbidden وupstream failure منفصلة؛ لا تحويل فشل الشبكة إلى قائمة فارغة. |
| التصميم | نظام Premium موحد، iconography Vector، حركة وصولية، واستجابة للغات الست. |
| الفهرسة | البداية العامة فقط مفهرسة؛ المسارات الخاصة `noindex` والكتالوج المختلط `noindex`. |

## ترتيب الاستكمال الحقيقي

الأولوية القادمة ليست اختراع شاشة جديدة؛ بل إغلاق العقود الخلفية التي تفتح رحلات كاملة بصورة آمنة: **OTP، تفاصيل الرعاية المنزلية، تفاصيل الوصفات، تفاصيل المحادثة/المرفقات/المكالمات، DTO هوية الملف، وتصنيف نشر الأدوية**. بعد كل عقد جديد، يضاف BFF typed parser وallowlist واختبار SSR واختبار Sandbox ملكية قبل إظهار أي UI عملي.
