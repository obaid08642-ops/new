## ما نُفّذ فعلياً

بُني تطبيق مريض بـ**Next.js 16.3.1 App Router** وTypeScript strict، واتصاله بالمنظومة الحية يمر عبر BFF خادمي. تُحفظ جلسة المريض في cookies من نوع `httpOnly`، ولا تُرسل توكنات Bearer إلى المتصفح أو `localStorage`. لا تستخدم أي رحلة إنتاجية بيانات demo أو نجاحاً محلياً مصطنعاً عند فشل الخلفية.

| المجال | ما اكتمل |
|---|---|
| البنية والأمن | BFF خادمي، جلسة JWT مع refresh واحد مقيد، allowlist لمسارات BFF، وحماية من BOLA/IDOR في الرحلات ذات معرّف مورد حيث أتاح العقد اختبار الملكية. |
| اللغات والوصولية | اللغات الست: العربية والإنجليزية والأردية والهندية والبنغالية والفلبينية؛ RTL للعربية والأردية، وفحوصات الحركة المخفّضة. |
| نظام التصميم | هوية Premium لنبض بلس: خط نظام الجهاز دون تضمين SF، علامة Vector أصلية، glyphs للعلامات الحيوية، حركة 120–220ms عبر `opacity` و`transform` فقط، ولا emoji أو أزرار نمطية. |
| الدخول واللوحة | صفحة دخول آمنة، إدارة الجلسة والخروج، ولوحة مريض لا تعرض إلا الرحلات المعتمدة. |
| الرحلات الخاصة المكتملة للقراءة | الطلبات وتفاصيلها، المواعيد وتفاصيلها، الملف الصحي بالحقل المسموح، الأدوية وتفاصيلها، التشخيص وتفاصيل الحجوزات، الرعاية المنزلية كقائمة، الأسرة كقائمة محدودة، الإشعارات، الصحة، التذكيرات، الوصفات كقائمة مقيدة، والمحادثات كقائمة وصفية. |
| الخصوصية | اختبارات SSR تمنع تسرب التوكنات والمعرّفات والبيانات السريرية والأسعار والتقارير والملفات إلى HTML حيث ينطبق ذلك. |
| اكتشاف المحتوى العام | صفحة عامة بست لغات، canonical وhreflang وrobots وsitemap وmanifest و`llms.txt` وOpen Graph/Twitter وJSON-LD محافظ. المسارات الخاصة غير قابلة للفهرسة. |
| معالجة تعذر الخلفية | فشل الشبكة في BFF يتحول إلى `503 upstream_unavailable` بلا حمولة حساسة؛ صفحة الصحة تعرض حالة عدم توفر صريحة قابلة لإعادة المحاولة بدلاً من نجاح أو فراغ مصطنع. |

## التحقق الحالي

أُعيد تشغيل التحقق على فرع المراجعة الجديد بعد رفعه. نجح فحص الأنواع واختبارات الوحدة وبناء الإنتاج. تُعزل اختبارات Sandbox الحية افتراضياً لتجنب حد المعدل، ولذلك لا تعد ضمن التشغيل المحلي العادي.

| الأمر | النتيجة |
|---|---|
| `pnpm check` | ناجح |
| `pnpm test` | 55 ملف اختبار ناجحاً، 94 اختباراً ناجحاً؛ 14 ملف Sandbox و23 اختبار Sandbox متخطاة عمداً في التشغيل المحلي |
| `pnpm build` | ناجح؛ بناء Next.js 16.3.1 للإنتاج اكتمل |
| تحقق GitHub | SHA المحلي يساوي SHA على GitHub للفرع الجديد |

## متابعة التحقق بعد الرفع

أُعيد اختبار العقد الذي كان متعذراً للعلامات الحيوية في Sandbox بعملية قراءة منفردة، ونجح اختبارا قراءة ملخص المريض الحالي ورفضه بلا جلسة. لم يكتب الاختبار أي قيمة صحية ولم يطبعها. كما اجتاز تدقيق طبقة الاكتشاف العام ثلاثة اختبارات موجهة لـSEO وmanifest؛ تظل sitemap محصورة في البدايات العامة الست وتبقى صفحات الدخول والكتالوج المختلط تحت `noindex, nofollow, noarchive`.

## ما لا يزال متبقياً، ولماذا

المتبقي ليس واجهات شكلية يمكن ملؤها محلياً؛ بل هو رحلات يجب أن تظل مقفلة حتى تسلم الخلفية عقودها واختبارات ملكيتها. لا تُضاف أزرار أو صفحات وهمية لهذه البنود.

| الفجوة | أثرها الآن | ما يلزم من Backend قبل تنفيذ الويب |
|---|---|---|
| G-HOME-001 | الرعاية المنزلية قائمة فقط بلا تفاصيل أو تتبع أو تقارير. | `GET /home-care/bookings/{bookingId}` مع استنتاج المريض من JWT و`404` لغير المالك وDTO عرض محدود. |
| G-OTP-001 | الدخول بكلمة المرور متاح؛ دخول OTP غير مفعّل. | جلسة مباشرة بعد OTP أو `exchange_token` قصير العمر لاستبداله خادمياً، بلا توكن في URL أو المتصفح. |
| G-PROFILE-001 | تُعرض الحقول الصحية المسموحة فقط، لا هوية ملف موثوقة. | DTO عرض للملف يتضمن الاسم المعروض واللغة وتاريخ الميلاد والجنس ضمن حدود الخصوصية. |
| G-FAMILY-001 | قائمة العائلة لا تعرض IDs أو صلاحيات خام، لكنها لا تملك أسماء عرض موثوقة. | DTO أعضاء بعناصر `display_name` و`role` و`joined_at` فقط. |
| G-PRESCRIPTION-001 | قائمة الوصفات المختصرة متاحة، ولا صفحة تفاصيل أو صرف. | endpoint تفاصيل مملوك للمريض، اختبار Sandbox مالك/غير مالك، وDTO مقيد بلا ملفات أو تشخيص أو سعر. |
| G-CHAT-001 وG-RTC-001 | قائمة المحادثات وصفية فقط؛ لا رسائل ولا مرفقات ولا إرسال ولا مكالمات. | عقود تفاصيل/رسائل مع عضوية خادمية وpaging، ثم عقود realtime/room token قصيرة العمر للمكالمات. |
| G-SEO-002 | كتالوج الدواء العام يبقى `noindex`. | API عامة منفصلة بعناصر منشورة ومصنفة وslug ثابت؛ عندها فقط يمكن `Drug` JSON-LD وsitemap للتفاصيل. |
| G-NOTIFICATION-001 | مفاتيح الخلفية التقنية لا تعرض كنص للمريض، ولا أفعال إشعارات. | نص محلي جاهز أو keys معلنة ومقيدة لكل اللغات الست؛ وعقود mutations مستقلة لقراءة الإشعار/التسجيل. |
| G-DATA-004 | لا يظهر عدّ مزودين مشتق محلياً؛ إعادة تحقق آمنة وجدت أن حقل `count` الرقمي الوحيد يساوي صفراً في 42 سجلاً، مع بقاء اكتشاف الأطباء غير فارغ. | contract منشور لعدد مزودي التخصصات متسق مع نتائج الاكتشاف. |
| G-OAPI-001 / G-OAPI-002 | الاعتماد الحالي على BFF + Zod واختبارات Sandbox. | OpenAPI مكتمل: servers، security، schemas، responses والأخطاء للعمليات الحساسة. |
| G-FILE-001 | لا رفع وثائق أو تقارير أو OCR. | عقد منح upload، MIME/size، URL موقّع قصير العمر، وملكية القراءة والحذف. |

## الخطوة الصحيحة التالية

المسار الصحيح هو تسليم الخلفية لأحد العقود الحرجة، ثم تنفيذ دورة محكومة: محلل DTO في BFF، allowlist للحقول، اختبار Sandbox للمالك مقابل غير المالك، اختبار SSR لمنع التسرب، ثم واجهة Premium تعمل ببيانات حقيقية فقط. ترتيب التسليم المقترح هو: تفاصيل الرعاية المنزلية وDTO الملف الشخصي، ثم OTP وDTO العائلة، ثم الوصفات والمحادثات، ثم تصدير OpenAPI وتصنيف الكتالوج العام.
