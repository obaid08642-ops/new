# إطار قياس SEO وGEO — نبض بلس

## المبدأ

يقيس هذا الإطار قابلية الاكتشاف والأثر الفعلي بعد النشر، ولا يَعِد بمرتبة أو نتيجة أو استشهاد من محرك بحث أو نظام إجابة. لا يجوز جمع عبارات بحث من حسابات مرضى، ولا تُرسل أي بيانات صحية أو معرّفات جلسة إلى أدوات القياس. تبدأ القياسات فقط بعد نشر نطاق إنتاجي وتحقق ملكيته في الأدوات المناسبة.

| الطبقة | السؤال التشغيلي | مصدر القياس | ما لا يعنيه المؤشر |
|---|---|---|---|
| الفهرسة | هل الصفحة الرئيسية قابلة للزحف والفهرسة؟ | URL Inspection وPage Indexing | ليس ضماناً لظهور النتيجة لكل مستخدم |
| البحث العضوي | كيف تتغير النقرات والانطباعات وCTR بحسب الصفحة/الاستعلام/البلد؟ | Search Console Performance | لا تثبت قيمة طبية أو توصية أو ترتيباً ثابتاً |
| الجودة التقنية | هل وصلت canonical وhreflang وJSON-LD والموارد؟ | URL Inspection وRich Results وCore Web Vitals | لا تستبدل تدقيق المحتوى والتحرير الطبي |
| Bing | هل قُدم sitemap وهل تظهر الأخطاء والإحصاءات؟ | Bing Webmaster Tools/API | لا يثبت إجابة مولدة أو نتيجة من نظام آخر |
| GEO | هل تذكر الأنظمة الإجبارية صفحات عامة موثقة عند أسئلة اختبار ثابتة؟ | سجل ملاحظة يدوي دوري | ليست قياساً شاملاً أو عينة تمثيلية أو وعداً بالاستشهاد |

## خط أساس وقواعد المقارنة

قبل أي تحسين، يسجل الفريق نسخة النشر، نطاق الإنتاج، قائمة URLs العامة المؤهلة، تاريخ التغيير، اللغة، ومعرّف الإصدار. تقارن النتائج بفترات متماثلة زمنياً، ولا يربط تغيير بعمل محدد إذا تزامن مع أكثر من تغيير جوهري في المحتوى أو التقنية.

| التواتر | الإجراء | قرار متوقع |
|---|---|---|
| عند النشر | تحقق ملكية Search Console وBing، إرسال sitemap، فحص `/ar` و`/en` عبر URL Inspection | إصلاح عائق زحف أو `noindex` غير مقصود قبل طلب الفهرسة |
| أسبوعي لأول 8 أسابيع | مراجعة حالة sitemap والفهرسة والأخطاء وCore Web Vitals | فتح تذكرة هندسية فقط عند خطأ موثق |
| شهري | تصدير Performance بحسب الصفحة والاستعلام والبلد واللغة | اختيار فرضية محتوى أو تقنية واحدة قابلة للقياس |
| ربع سنوي | مراجعة GEO يدوية على استعلامات غير طبية وحساسة ثابتة | تسجيل الوجود/الغياب والسياق فقط؛ لا تكرار الاستعلامات بكثافة أو استخدام الاستنتاج كدليل ترتيب |

## سجل GEO اليدوي

لا يُنفذ أي جمع آلي أو تحايل على منصات الإجابة. يكون الاختبار يدوياً من حساب مؤسسي، بأسئلة تعريفية عن المؤسسة أو صفحاتها العامة، ومن دون أي حالة مريض أو سؤال تشخيصي. يوثق السجل التاريخ والمنصة والبلد/اللغة والاستعلام وURL الذي ظهر والسياق ولقطة داخلية منقحة، ثم يميز النتيجة بـ«ظهر» أو «لم يظهر» أو «غير قابل للتقييم». لا تحول نتيجة واحدة إلى ادعاء تسويقي.

## بوابة الخصوصية والجودة قبل أي KPI

لا تضاف صفحة إلى قائمة القياس إلا إذا كانت عامة بالفعل، تحتوي canonical صحيحاً، لا تتطلب دخولاً، لا تحمل معلومات مريض، ولا تضع JSON-LD يتجاوز محتواها الظاهر. يبقى كتالوج العناصر المختلط خارج قائمة القياس العضوي وGEO حتى يضيف Backend تصنيف نشر ودواء موثوقاً.

> توضح Google أن Search Console يعرض حركة البحث بحسب الاستعلامات والصفحات والبلدان، وأن URL Inspection يفيد لاختبار قابلية الفهرسة وفحص النسخة التي تراها Google. [1] [2]

> لا يضمن طلب إعادة الزحف تضمين الصفحة في النتائج؛ وتظل الجودة والفائدة من شروط الأولوية. [3]
