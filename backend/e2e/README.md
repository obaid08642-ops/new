# Nabdah Plus — Live E2E Scenario Matrix (بيئة الاختبار الحية الداخلية)

بيئة اختبار حقيقية كاملة: قاعدة MongoDB حقيقية (mongodb-memory-server) + Redis حقيقي +
نسخة الإنتاج المبنية من الباك إند (`dist/`) — بلا أي محاكاة على مستوى الطلبات.

## المتطلبات

1. بناء الباك إند أولاً: `npm ci && npm run build` (من جذر الريبو).
2. Redis على المنفذ `6388` — أحد الخيارات:
   - شغّل `redis-server --port 6388` بنفسك، أو
   - عيّن `REDIS_E2E_BIN=/path/to/redis-server` وسيتم تشغيله تلقائياً.
3. تثبيت اعتماديات الحزمة: `cd e2e && npm install`.

## التشغيل

```bash
# من جذر الريبو بعد npm run build
node e2e/boot.js &        # يشغّل MongoDB الذاكري + الباك إند على :4099 ويكتب e2e URI عند الجاهزية
node e2e/matrix.js        # يشغّل 65 سيناريو حياً ويطبع النتائج
```

## تغطية المصفوفة (65 سيناريو)

| القسم | السيناريوهات |
|---|---|
| A | التسجيل/الدخول، حظر NoSQL injection، كلمة المرور الضعيفة، 2FA للأدمن |
| C | كل أنواع الاستشارات (عيادة/فيديو/منزلية) × كل طرق الدفع (نقدي/بطاقة/تأمين) — سياسة BR-1 |
| D | آلة حالات المواعيد: تأكيد، تسجيل وصول، بدء، إنهاء، إلغاء، إعادة جدولة، حظر الانتقالات غير الشرعية، حظر الغرباء |
| E | دورة التأمين كاملة BR-2: تقديم، موافقة كلية/جزئية، copay، رفض بسبب، حظر مزود خاطئ، قائمة الأدمن |
| F | الصيدلية: إنشاء طلب، طلباتي، البحث العام |
| G/H/I | التحاليل، الأشعة، التمريض المنزلي (الفهارس العامة + محاولات الحجز) |
| J | جهة المزود: صندوق المواعيد، التوفر، طلبات الإجازة (تخزين حقيقي)، الطلبات الواردة |
| K | لوحة الأدمن: المالية، الدعم، feature flags، إحصاءات الإشعارات، سجلات التدقيق، إدارة المستخدمين + الحظر، حظر RBAC |
| L | الإشعارات: القائمة + الجدولة عبر BullMQ على Redis حقيقي |
| M | السوكيت: رفض بدون JWT، اتصال بـ JWT صالح |
| N | المكالمات: إنشاء جلسة LiveKit + استلام JWT للانضمام |
| O | SEO/GEO: sitemap.xml، meta/JSON-LD، **llms.txt** لمحركات الذكاء الاصطناعي |
| P | الاسترداد: نوافذ السياسة 100%/50%، التحقق من السبب |

النتيجة المرجعية الحالية: **65 ناجح / 0 فاشل / 0 متخطى**.

## ملاحظات

- مفاتيح البيئة في `boot.js` قيم اختبار فقط (`sk_test_e2e_boot_only`) — لا تستخدمها خارج الاختبار.
- قاعدة البيانات تُنشأ نظيفة في كل إقلاع وتُبذر داخل `matrix.js`.
- سجل الباك إند يُكتب إلى `/tmp/e2e/backend.log` (عدّل المسار داخل boot.js عند الحاجة).
