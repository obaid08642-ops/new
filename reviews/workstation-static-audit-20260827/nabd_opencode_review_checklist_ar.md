# قائمة مراجعة تعديلات OpenCode لمنصة Nabd

## خط الأساس

سيكون المرجع البرمجي هو `obaid08642-ops/new@main` عند الالتزام `22526bedb77a3d8148219036367e4714f401aecc`. ستقارن كل نسخة محلية بالملفات المتتبعة في هذا الرأس، ثم تفصل بين الفروق المتتبعة والملفات الجديدة وغير المتتبعة والإعدادات المحلية.

## ما الذي ستفحصه المراجعة

| محور | دليل مقبول | لا يكفي وحده |
|---|---|---|
| الفروق البرمجية | diff قابل للقراءة، الملفات المتأثرة، العقد والاختبارات ذات الصلة | وجود ملف أو شاشة جديدة فقط |
| العقود والبيانات | endpoint/DTO/schema/migration/state transition وsource-of-truth | mutation أو حالة نجاح محلية |
| الصلاحيات والخصوصية | خادم يفرض role/tenant/ownership/consent مع اختبار رفض | route guard أو زر مخفي في العميل |
| المال والتغطية | PSP/payer/ledger/idempotency/reconciliation evidence | صفحة نجاح أو قيمة ثابتة |
| السريري والذكاء الاصطناعي والطوارئ | safety pack، provenance، escalation، feature gate | واجهة أو prompt أو mock response |
| تجربة المستخدم | loading/empty/error/offline/denied/retry وRTL/accessibility | happy path أو screenshot فقط |
| الاختبارات | unit/contract/integration/E2E/runtime evidence مناسب للتغيير | build أخضر أو mock test وحده |
| الدمج | لا أسرار، لا ملفات build/cache، ترحيلات واضحة، rollback وخطر محدد | دمج شامل بلا تجزئة أو مراجعة |

## حالات الحكم لكل متطلب

كل بند من مخطط التحول ومصفوفة الشاشات سيأخذ واحدة من الحالات: **منفذ بدليل**، **منفذ جزئياً**، **غير منفذ**، **محجوب عمداً**، أو **غير قابل للتحقق من مراجعة المصدر وحدها**. ولا تستخدم عبارة «جاهز للإنتاج» إلا إذا توافرت الأدلة التشغيلية المذكورة في المخطط.
