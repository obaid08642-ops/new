# خط أساس مراجعة خطتي Nabd

## الغرض

هذه الوثيقة لا تحكم بعد على تنفيذ OpenCode؛ بل تثبت ما الذي يجب مقارنته عند وصول نسخة المشروع المحلية. لا يجوز اعتبار وجود شاشة أو build ناجح دليلاً على الجاهزية الإنتاجية، لأن مخطط التحول يجعل العقد والأمن والتشغيل والاختبارات الحية شروطاً مستقلة.

## المطلوبات المستخرجة من الوثيقتين

| المصدر | ما يفرضه | أثره على المراجعة |
|---|---|---|
| مخطط التحول الإنتاجي | حالة `NO-GO` حتى تمر طبقات المنتج والعقد/البيانات والأمن/الخصوصية والتشغيل والتجربة وruntime | كل تعديل يجب فحصه كدليل جزئي، لا إعلان جاهزية. |
| مخطط التحول الإنتاجي | مصدر الحقيقة للخدمات المالية والسريرية والهوية والتغطية والحجوزات يبقى خادمياً | أي منطق client-only أو mock أو قيمة مالية/سريرية ثابتة يعد مخاطرة أو دليلاً ناقصاً. |
| مصفوفة المسارات | 242 صف route/CTA مستخرج من التدقيق: 189 `BUILD` و53 `COMPLETE_OR_REPLACE` | ستقارن النسخة المحلية بهذه الصفوف، مع تمييز الواجهة عن العقد والتشغيل. |
| مصفوفة المسارات | أسطح Provider/Admin تحمل `AUDIT_FIRST` ولا تبني كقائمة نهائية قبل التدقيق والعقود | لا يقبل وجود UI وحده كتنفيذ. |
| مصفوفة المسارات | مسارات `P0-SAFETY` السريرية والطوارئ والذكاء الاصطناعي محجوبة قبل safety pack | أي كشف أو تفعيل بلا أدلة سلامة يمثل خطراً عالياً. |

## مجالات المقارنة

تشمل المصفوفة، من بين مجالات أخرى، الهوية والخصوصية والأسرة، الصيدلية والعروض والطلبات، الحجوزات والاستشارات والمكالمات، التشخيص والرعاية المنزلية، التأمين والمدفوعات، التقارير الصحية، الدعم والإشعارات، والمحتوى. كل قدرة ستسجل بإحدى الحالات التالية: `منفذ بدليل` أو `منفذ جزئياً` أو `غير منفذ` أو `غير قابل للتحقق من المصدر` أو `محجوب عمداً`.

## حدود المراجعة

لن يتم تشغيل نسخة OpenCode أو أي migration أو package script قبل فحصها. وسيبقى الحكم على التكاملات الحية وPSP/payer/clinical/runtime بصيغة **غير قابل للتحقق من مراجعة المصدر فقط** ما لم تتوافر أدلة اختبار وتشغيل مناسبة.
