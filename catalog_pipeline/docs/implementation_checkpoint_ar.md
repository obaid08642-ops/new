# نقطة تنفيذ أولى — خط إصدارات الكتالوج

**التاريخ:** 2026-08-20
**الحالة:** اكتمل الأساس التقني للإدخال الآمن، الحوكمة، التوقيع، والتحقق. لم يُنشر أي سجل من بياناتك العامة، وهذا مقصود وصحيح في هذه المرحلة.

## ما تم تنفيذه

تم تحديث عقد الكتالوج المعتمد في `catalog_release_contract_ar.md`. يثبت العقد التقسيم `لغة ← فئة رئيسية ← نطاق معرّف ثابت ← شظية gzip`، ومؤشر `latest.json` قصير الكاش، وإصدارات immutable، وSHA-256 لكل artifact، وتوقيع Ed25519 للـmanifest، وproduct index مباشر، وtombstones، وفصل البيانات التجارية المتغيرة عن كتالوج المحتوى الثابت.

| المكوّن | الملف أو المجلد | النتيجة |
| --- | --- | --- |
| سجل اللغات | `config/locales.json` | ست لغات معرفة بالاتجاه والـfallback وحالة النشر الأولية |
| سياسة النشر | `config/release_policy.json` | هدف shard 150–400 KiB، حد أقصى 1 MiB، وبوابة الحوكمة الإلزامية |
| مخطط السجل الداخلي | `schemas/canonical_record.schema.json` | فصل للحقائق المشتركة واللغات والأدلة والصور وحالة الحوكمة |
| مخطط الـmanifest | `schemas/release_manifest.schema.json` | تحقق من الإصدار واللغة والفهرس والشظايا والبصمات والتوقيع |
| الاستيراد الحتمي | `scripts/import_raw_catalog.py` | تحويل الخام إلى JSONL معياري بدون افتراض صحة أو قابلية نشر |
| مولد الإصدار | `scripts/build_release.py` | تجزئة gzip وفهرس منتجات وتوقيع manifests وحاجز أهلية |
| التحقق المستقل | `scripts/verify_release.py` | تحقق schema وتوقيع Ed25519 وSHA-256 وعدد السجلات |

## اختبار بوابة الحوكمة على الملف الحالي

## اختبارات التكامل المنفذة

أُنشئ اختباران معزولان داخل `tests/`، ولا يؤثران على البيانات الخام أو الملفات العامة.

| الاختبار | النتيجة |
| --- | --- |
| اختبار حاجز الحوكمة | أنشأ manifests موقعة مع zero public records، وتحققت التواقيع والبصمات لجميع اللغات بنجاح |
| اختبار شظية غير فارغة | استخدم سجلاً حقيقياً في نسخة اختبار مع قرار اعتماد اصطناعي ومُعلن للاختبار فقط؛ أنشأ product index وshard عربية وإنجليزية، وتحققت التواقيع وSHA-256 وعدد السجلات بنجاح |

أظهر اختبار الشظية غير الفارغة أن سجل المنتج الغني ذي الوصف الطويل بلغ 1.1 KiB مضغوطاً في العربية و1.0 KiB في الإنجليزية عند كونه سجلاً واحداً. لذلك يظل هدف 150–400 KiB مناسباً، لكن لا ينبغي تثبيت «1,000–2,000 سجل في الشظية» كقاعدة مطلقة؛ القياس المضغوط الفعلي هو الحاكم، وسيحدد العدد النهائي بعد معالجة عينة معتمدة حقيقية.

## ما لم يُنفذ عمداً بعد

لم ينفذ هذا الإصدار الأول تنظيفاً دلالياً أو ترجمة آلية أو تصنيفاً طبياً أو سحباً جماعياً من واجهات خارجية. هذه عمليات تحتاج السياسة المعتمدة ومراجعة المصدر، ولا ينبغي أن تسبق بنية السجل والحاجز الذي يمنع النشر الخاطئ.

| المرحلة التالية | الشرط السابق لها |
| --- | --- |
| اعتماد سجل اللغات النهائي | تأكيد هل اللغات الست الحالية نهائية، وحالة الفلبينية ومتى يسمح بالـfallback |
| اعتماد شجرة الفئات العشر | تسميات ومعرفات ثابتة، مع `product_kind` مستقل وفلاتر ثانوية |
| بناء مولد slug محكوم | سياسة transliteration وredirects والـcanonical لكل لغة |
| معايرة AR/EN | عينة مراجعة تمثل الأدوية والمنتجات غير الدوائية والحالات الحساسة |
| طابور التحقق الخارجي | استخدام API وsitemap للتحقق الموجَّه، لا النسخ الجماعي |
| تحديث الحوكمة | تغيير حالات السجل بعد دليل ومراجعة مع تسجيل السبب والمصدر |
| أول release حقيقي | لا يبدأ قبل اجتياز بوابة الحوكمة والتوقيع والاختبارات |

## حماية مفاتيح التوقيع

توجد مفاتيح Ed25519 محلية للتطوير فقط في `keys/`، والمفتاح الخاص مستبعد من Git عبر `.gitignore`. عند النشر الفعلي يجب استخدام مدير أسرار مناسب ومفتاح إنتاج منفصل؛ لا ينقل مفتاح التطوير أو المفتاح الخاص إلى تطبيق Expo أو مستودع عام.
