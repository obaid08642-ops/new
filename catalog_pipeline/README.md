# Catalog Pipeline

هذا المشروع هو خط المعالجة الأولي لكتالوج منتجات متعدد اللغات. لا يهدف إلى نشر الملف الخام الحالي مباشرة. بل يحوّله إلى سجلات داخلية معيارية قابلة للمراجعة، ثم يسمح فقط لمولد الإصدار بإخراج السجلات التي اجتازت بوابة الحوكمة المحددة في `config/release_policy.json`.

## المبادئ

| المبدأ | التطبيق |
| --- | --- |
| مصدر حقيقة واحد | `data/internal/canonical_records.jsonl.gz` يحتفظ بالحقائق والأدلة واللغات |
| لا نشر افتراضي | السجلات المستوردة تبدأ بحالة `draft` و`public_eligibility=false` |
| لغة واحدة لكل artifact | يبنى manifest وproduct index وشظايا مستقلة لكل لغة |
| شظايا مستقرة | `locale/main_category_id/id-range` مع ترتيب ثابت بالمعرف |
| rollback آمن | كل إصدار immutable و`latest.json` فقط هو المؤشر المتحرك |
| تحقق موقّع | manifest موقّع بـEd25519 والشظايا تتحقق بـSHA-256 |

## البنية

```text
config/      سجل اللغات وسياسة الإصدار
schemas/     JSON Schema للسجل الداخلي والـmanifests
scripts/     الاستيراد، التوليد، التحقق، والتوقيع
data/raw/    نسخة المصدر الخام المضغوط
data/internal/  السجل المعياري الناتج؛ غير مخصص للنشر
releases/    artifacts الإصدار المؤهلة للنشر
keys/        مفاتيح توقيع محلية للتطوير فقط؛ لا ترفع مفاتيح الإنتاج
```

## التسلسل

1. ضع ملف المصدر المضغوط في `data/raw/`.
2. شغّل `scripts/import_raw_catalog.py` لتحويل السجلات إلى JSONL معياري مع أدلة المصدر وحالات حوكمة آمنة.
3. عالج التصنيف والترجمة والمراجعة في قاعدة البيانات أو عملية المراجعة المعتمدة.
4. شغّل `scripts/build_release.py` مع `--dry-run` لمراجعة أسباب الحجب قبل النشر.
5. بعد اعتماد سجلات مؤهلة فعلاً، شغّل مولد الإصدار لإنشاء manifests والشظايا وفهرس المنتجات.
6. شغّل `scripts/verify_release.py` للتحقق من مخطط الملفات والبصمات والتوقيع قبل رفع الإصدار إلى CDN.

## تحذير إنتاجي

مفاتيح التطوير التي يولدها هذا المشروع ليست مفاتيح إنتاج. في الإنتاج، تحفظ مفاتيح التوقيع في مدير أسرار منفصل، ولا يدخل المفتاح الخاص إلى مستودع الكود أو حاوية تطبيق الهاتف.
