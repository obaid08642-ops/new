# تدقيق مستهلكي كتالوج التأمين الموحد

**التاريخ:** 20 أغسطس 2026
**الفرع المقصود:** `manus/on-live-reconciliation` فقط
**النطاق:** تطبيق Patient، تطبيق Provider، لوحة Admin، وعقد Backend الخاص بشركات التأمين والشبكات.
**الحكم المصدرّي:** مكتمل لهذه الدفعة؛ لا تبقى قائمة شركات أو فئات تأمين ثابتة في المصدر التشغيلي. لا يتضمن ذلك نشر أي تطبيق أو تنفيذ migration على قاعدة البيانات الحية.

> مصدر الشركات والفئات التشغيلي الوحيد هو Backend: `GET /insurance/companies` ثم `GET /insurance/companies/:id/networks`. لا يجوز للواجهة تركيب fallback محلي عند تعذر المصدر؛ تعرض حالة عدم توفر أو قائمة فارغة آمنة. يحمل رد الشركة `logo_url` عند نشر أصل مدقق، وتعرض الواجهات الشعار المتاح فقط بجانب الاسم ولا تولّد بديلاً بصرياً.

## 1. منهج التدقيق

تم البحث في ملفات TypeScript/JavaScript المصدرية فقط عبر `patient/app` و`patient/src` و`provider/src` و`admin/src`، مع استبعاد حزم البناء و`node_modules` وملفات الترجمة. شمل البحث كلمات العقد، أسماء الشركات، ثوابت الفئات، ومسارات API. ثم فُحص كل مرشح تشغيلي يدوياً، وأعيد الفحص بعد الإصلاح حتى لم يبق أي مرجع تشغيلي لبيانات الكتالوج المحلية.[1] [2]

| نتيجة الجرد | العدد/الحالة | الدليل |
|---|---:|---|
| استدعاءات مرتبطة بالتأمين قبل التصنيف | 2,614 سطراً | ملف الجرد الخام [1] |
| مسارات ثابتة تشغيلية مكتشفة | 2 | فلتر الاستشارات في Patient، وإعدادات/توفر الطبيب في Provider |
| مصادر كتالوج ثابتة متبقية بعد المعالجة | 0 | فحص ما بعد الإصلاح [3] |
| شركات الكتالوج الحي المقروءة | 30 | فحص قراءة فقط لـAPI في 20 أغسطس 2026 |
| شبكات أول شركة حيّة مقروءة (Bupa) | 17 | فحص قراءة فقط لـAPI في 20 أغسطس 2026 |

## 2. تغطية تطبيق Patient

| التدفق | المصدر الحالي للشركة/الفئة | القرار |
|---|---|---|
| استكشاف الاستشارات وفلتر التأمين | `GET /insurance/companies` ثم شبكات الشركة المحددة | أصلح؛ أزيل قاموس `saudiInsurances` المحلي ومطابقة الأسماء الهشة. الفلترة تعتمد معرّف الشركة و`insurance_plans` إن كانت الفئة محددة. |
| تأكيد حجز الاستشارة | الكتالوج والشبكات من Backend | مربوط وfail-closed عند فشل التحميل؛ يعرض `logo_url` الرسمي بجانب اسم الشركة إن توفر. |
| رفع وثيقة التأمين للتحاليل | الكتالوج والشبكات من Backend | أصلح؛ أزيل fallback Bupa/Class B المحلي، ولا يوجد اختيار افتراضي. |
| ملف المريض > التأمين | الكتالوج والشبكات من Backend | كان مربوطاً؛ تم التحقق من التحميل ديناميكياً. |
| إضافة بوليصة تأمين | `GET /insurance/companies` | كان مربوطاً؛ لا توجد قائمة محلية. |
| الصيدلة والتمريض المنزلي والأشعة والتحاليل بعد وجود الوثيقة | طلبات/تغطية وبوليصة Backend، وليس اختيار كتالوج محلي | لا يوجد مستهلك ثابت للشركات أو الفئات في هذه التدفقات. أي شركة محفوظة تأتي من وثيقة المريض أو طلب التغطية الخادمي. |

تم حذف `patient/src/constants/insurance.ts` بعد تحقق عدم وجود أي مستورد له؛ لذلك لم يعد الملف القديم مصدراً ثانياً يمكن أن تعود إليه الشاشات مستقبلاً.

| لوحة الإعدادات المشتركة للمزودين | `useInsuranceCatalog()` + `/provider-onboarding/my-profile` + `/provider/settings/delta` | مرتبط؛ يسترجع القبول والفئات ونسب التحمل الخادمية، ويرسل delta تدقيقياً، ويعرض `logo_url` الرسمي المتاح لكل شركة بجانب الاسم لجميع أنواع المزودين الستة. |
| إعدادات تأمين الطبيب | الشاشة المشتركة نفسها | أصلح؛ حُوّل route الطبيب إلى `SharedInsuranceConfigScreen` وحُذف مكوّن الطبيب المحلي الثابت. |
| شاشة توفر الطبيب | لا تضبط التأمين | أصلح؛ أزيلت كتلة شركات/فئات نموذجية كانت تحفظ محلياً ضمن جدولة التوفر. إعداد التأمين له شاشة موحدة مستقلة. |
| لوحة الطبيب > ملف المريض | لا تعرض تأميناً بلا عقد مريض | أصلح؛ أزيلت شارة `Bupa A` الافتراضية. |
| لوحات المختبر/الأشعة/الصيدلية/التمريض/المنشأة | endpoints طلبات/تغطية Backend عند الحاجة | لا توجد قوائم شركات أو فئات ثابتة في المصدر التشغيلي. |
| تسجيل الإسعاف | لا توجد واجهة اختيار شركات حالياً | لا تظهر قائمة ثابتة؛ حقل `acceptedInsurance` غير معروض ككتالوج. يجب ربطه بالشاشة المشتركة قبل تفعيل اختيار التأمين لهذا النوع مستقبلاً. |

تمت إزالة ثابت `INSURANCE` من `provider/src/constants/index.ts`، وكذلك استيراداته الستة الموروثة في شاشات التسجيل؛ وبذلك لا يبقى مصدر واجهة محلي لشركات أو فئات التأمين.

## 4. تغطية لوحة Admin

صفحة إدارة الشركات `admin/src/pages/admin/insurance-companies.tsx` تستدعي `GET /insurance/companies/all`، وتدير الشركات والفئات عبر `POST/PATCH/DELETE` الخاصة بعقد Backend، وتعرض الشعار وحالة الكتالوج وعلاقة الخلف من الحقول الخادمية. لا تحتوي الصفحة قائمة شركات أو فئات ثابتة، ولا تسمح بالحذف النهائي للكيانات والفئات التاريخية. يبقى قرار إضافة شعار أو فئة جديد محكوماً بحقول provenance/review في Backend وبالتدقيق البشري؛ لا يجيز هذا التعديل اعتماد شعار أو فئة غير موثقة.

## 6. حدود هذا الحكم ومهام المراجع

هذا الحكم يعني أن **الشفرة المرشحة** لا تستخدم كتالوجاً محلياً لإظهار أو اختيار شركات وفئات التأمين. وهو لا يعني أن كل الشركات أو الشعارات أو الفئات في قاعدة البيانات صارت معتمدة تجارياً أو تنظيمياً. لا تزال العناصر التالية خارج نطاق الإغلاق الآلي:

| البند | الحالة المطلوبة |
|---|---|
| تشغيل smart backfill على البيانات الحية | مراجع/DevOps، مع dry-run وrollback موثقين. |
| نشر Backend أو تطبيقات الواجهة | مراجع/DevOps فقط؛ لا نشر في هذه الدفعة. |
| جمع الشعارات الرسمية المتبقية | مصدر الشركة الرسمي أو بيان صحفي/حزمة هوية رسمية فقط؛ `manifest.json` يضم 31 سجلاً: 19 شعاراً موثق المصدر و12 سجلاً معلّقاً. يمنع استخدام المجمعات أو الشعارات المولدة. |
| ربط أصول المرشح بالتخزين/CDN | أبلغ المالك أن 17 أصلاً نُشرت وتتحقق من CDN. يبقى رفع `gulf_general.webp` حصراً بعد المراجعة؛ أما `saudi_enaya.webp` فلا يربط أو يظهر للعامة قبل اعتماد علاقة الكيان/الخلف. |
| اعتماد فئات كل شركة | وثيقة منتج أو شبكة رسمية لكل شركة؛ لا تُعمم C1/C2/C3/A/B/VIP عبر الشركات بلا سند. |
| التحقق على أجهزة فعلية | المالك/فريق QA أو device farm، بما يشمل RTL وإتاحة الشعار وحالة الكتالوج غير المتاح. |
