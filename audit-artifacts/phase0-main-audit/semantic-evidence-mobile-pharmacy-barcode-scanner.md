# Semantic evidence — Mobile Pharmacy Barcode Scanner

Baseline: `22526bedb77a3d8148219036367e4714f401aecc`.

`audit-work/source/nabd_plus_patient_app/app/pharmacy/barcode-scanner.tsx:13–23,100–157` implements camera permission, barcode formats and capture UI. Permission denial has a request action, but there is no durable permission-denied guidance, camera failure state, retry/error distinction or privacy disclosure for scanning. Barcode data is accepted as a trimmed arbitrary string (`:87–92`) and sent to `/medicines/by-barcode/{code}` (`:60–85`) without visible format/length/scheme validation, request cancellation or server ownership/public-contract evidence. On a positive response it trusts `res.medicine`, sets `available: true` regardless of an explicit availability field, and routes product data by ID/name (`:63–75,96–98`).

The photo-identification flow captures base64 image data at quality 0.4 and posts it to `/ai/medicine-image-search` (`:25–38`). No visible size limit, retention policy, consent, PHI/label redaction, provenance/confidence, rate limit or Idempotency-Key is present. The returned AI name is then used to query `/medicines`, and the first item is selected without disambiguation or confidence/identifier reconciliation (`:39–50`). If no item exists it routes to generic search. The source exposes an AI action without an explicit blocked/error policy beyond a generic message.

A barcode result displays server-derived name/brand/dose/price fields but does not visibly validate currency, prescription state, stock freshness, expiry or product identity (`:64–75,166–196`). “عرض التفاصيل وإضافة للسلة” only navigates to product detail; actual cart mutation, prescription eligibility, quantity, server quote and account context are deferred and unproven. Unknown barcodes show a generic not-found state with AI/manual alternatives (`:201–217`), but no record of the scan or real manual-order contract is established. No Phase 0 remediation was made.
