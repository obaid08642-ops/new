# Phase 0B semantic evidence — FastAPI server

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Member read in full:** `infra/fastapi/server.py:1–1431` (read in segments through the end)

This FastAPI server is a parallel backend surface with MongoDB, JWT, R2/S3, an AI router and a NestJS proxy (`1–71`). It requires `MONGO_URL`, `DB_NAME` and `JWT_SECRET`, but uses a bearer token in the `Authorization` header and returns JWT tokens plus user documents from guest/register/login (`27–36,202–225,259–314`). The token lifetime is 30 days and there is no visible revocation/session rotation/device binding/refresh policy. `clean_doc` removes only `_id` and `password`; broad user/provider/clinical documents can still be returned. `get_current_user` accepts any `Authorization` value after string replacement, returns `None` rather than a typed auth failure, and fetches only by token user ID without active/role/tenant/revocation checks (`211–237`).

Startup creates a small set of indexes and conditionally runs `seed_test_data` when `NODE_ENV=test` and `ALLOW_TEST_SEED=true` (`247–255`), but no readiness/health contract, migration/index assertion, shutdown lifecycle for the Mongo client beyond `client.close`, or production target gate is visible. CORS allows credentials together with `allow_origins=['*']`, all methods and all headers (`1418–1425`), which is an unsafe cross-origin policy for bearer/session-sensitive endpoints. The server registers an AI router and NestJS proxy at import time, creating a parallel/duplicate contract surface (`57–71`).

Reference and catalog endpoints return broad collections with fixed limits and no public eligibility, tenant, approval, locale, source, inventory or pagination contract (`321–340`). Doctor listing filters active status but returns up to 500 records and performs in-memory search; detail returns broad doctor data and approved reviews without a minimum-necessary projection (`343–375`). Doctor onboarding accepts base64 license/avatar and pricing fields directly, inserts user and doctor records in two independent writes, and exposes no idempotency, verification transaction, upload-size/type or duplicate identity guard (`377–417`).

The product catalog maps `fil` to `tl`, uses unbounded regex search from user input, returns translations and many catalog fields, and has inconsistent numeric/string product-ID handling and a fallback to a second `products` collection (`428–501,522–579`). Product/alternative responses do not visibly enforce public eligibility, current stock, seller/pharmacy, regulatory status, price currency or safe projection. Scarcity reporting trusts product/pharmacy IDs and user note without ownership, existence, rate-limit, dedupe or moderation controls (`503–520`). Visual search sends user-supplied base64 to an LLM, extracts arbitrary JSON with regex, returns a fallback/error based on unverified model output, and scans up to 500 products; no size/type/privacy/medical-safety/grounding/confidence gate is visible (`582–640`).

Appointment creation verifies only that a doctor exists, reads `price_{mode}`, and inserts a scheduled appointment with patient name/phone, notes and insurance in one non-idempotent write; no slot lock, time validation, doctor availability, ownership/participant relationship, payment/insurance truth, currency, transaction or duplicate prevention is visible (`643–673`). Appointment completion checks only existence, not actor ownership/doctor relationship or current state, then independently updates appointment and chat room; this is a cross-user authorization and consistency risk (`683–700`). Orders accept arbitrary items/payment method/address/prescription base64, silently skip missing products, trust product prices from `db.products`, do not validate quantities or pharmacy ownership, and insert pending orders without idempotency, inventory reservation, totals/tax/currency, payment authorization or atomicity (`703–739`).

Chat message reads and writes filter only by `room_id` and create a room for any authenticated user; there is no participant check before history/send, and the WebSocket accepts and broadcasts without token authentication or participant authorization (`746–817`). Messages store raw text/image/voice base64 and sender metadata; no size/type/redaction/retention/abuse or closed-room enforcement exists for the WebSocket path. Health Passport creates and updates sensitive clinical data with user ID scope but uses a generic dictionary for updates, no validation, versioning, consent, audit, idempotency or deletion lifecycle (`818–856`). Vitals are appended with no physiological bounds or duplicate policy (`837–845`). Reminders insert arbitrary names/dose/times/dates without validation, idempotency or schedule conflict handling (`859–880`).

Reviews accept arbitrary target type/id and rating without range, target existence, completed-service or one-review-per-experience enforcement. Ratings >=4 are auto-approved; doctor aggregate calculation is a read-then-write race and can be stale, and approval/deletion lacks state/actor audit (`883–921`). Tickets accept unauthenticated PII and message content and store it without rate limiting, abuse control, consent or structured triage; admin listing returns broad ticket data (`924–945`). Admin statistics loads up to 10,000 orders and sums client/database totals without currency/settlement reconciliation (`948–963`). Admin users/doctors/orders/appointments expose broad records; admin doctor verify updates doctor and user in separate writes; order status accepts arbitrary status in a generic dictionary; delete/toggle operations do not expose version, audit or dependent-data handling (`965–1015`).

Admin product CRUD accepts generic dictionaries, defaults price to zero and `in_stock` true, permits arbitrary image/description/manufacturer, updates/deletes without existence/version/audit/source/approval and uses unbounded-ish limits (`1017–1057`). Pharmacy product image management allows arbitrary filenames/content types and direct R2 deletion/upload; presigned URLs expose storage operations without filename/path sanitization, MIME/size/dimension checks, ownership of product, atomic DB/object coupling or rollback (`1060–1188`). Settings are initialized from hardcoded commission, delivery, tax, support and radius defaults; updates accept any allowed key/value with no bounds, currency/effective version, audit or financial approval (`1191–1217`).

Virtual clinic grouping uses hospital names as slugs by replacing spaces, returns doctor documents and averages without canonical facility identity, locale/timezone, licensing or privacy controls (`1220–1271`). Notifications allow role-wide delivery, list by role/user, mark one by notification ID without constraining the update to recipient/role, and admin can insert arbitrary title/body/type; no idempotency, dedupe, expiry, PII, abuse or delivery audit is visible (`1274–1324`).

AI triage has a keyword fallback when the LLM key is absent, always labels the response successful and routine, and provides no red-flag emergency escalation, disclaimer, clinical validation, structured schema enforcement or grounding (`1327–1364`). The LLM path parses arbitrary JSON and on any error returns a successful routine recommendation, which is medically misleading (`1365–1395`). Agora token endpoint explicitly returns `token: None` in development mode and accepts arbitrary channel data; it is authenticated only by a possibly weak bearer helper and provides no production fail-closed guard, authorization, expiry or participant binding (`1398–1409`). The root endpoint returns status/time but no readiness distinction (`1412–1415`).

The file therefore represents a large parallel legacy/compatibility surface with high-risk divergences from the contract-first NestJS baseline: wildcard credentialed CORS, bearer tokens in bodies, broad PII/clinical projections, BOLA in appointment/chat/admin paths, non-atomic financial/clinical writes, unverified AI fallbacks, insecure uploads and destructive/admin mutations. No product code was changed and no tests/builds or runtime calls were executed during this semantic read.
