# Phase 0B semantic evidence — FastAPI development seed data

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Member read in full:** `infra/fastapi/seed_dev.py:1–534`

`seed_dev.py` is a large disposable-fixture module for the parallel FastAPI backend, containing Saudi cities/districts, specialties, insurance companies/tiers, lab tests/prices, radiology services/prices, sample doctors, pharmacies and pharmacy products (`1–509`). It describes itself as comprehensive seed data and includes records presented as realistic/operationally meaningful. There is no source/provenance, jurisdiction/effective date, regulatory review, catalog version, currency/tax metadata, approval actor, serviceability source or explicit distinction between demonstration data and public truth in the records.

The dataset includes medical/service prices, prescription flags, license verification, active status, doctor credentials, ratings/review counts, availability/next slots/wait times, pharmacy addresses/coordinates/phones/opening status, stock counts, manufacturers and external Unsplash/Pexels images (`137–509`). These fields are hardcoded and not linked to authoritative provider, licensing, inventory, scheduling, rating, image ownership or pricing systems. Several data values are user-facing claims: `license_verified: True`, `status: active`, ratings/review counts, `available_today`, `next_slot`, `wait_time_min`, delivery fees, stock and prescription flags. Medical tests/radiology services have hardcoded prices without currency/source/effective dates or lab/facility availability and safety metadata (`159–245`).

The seed function inserts each collection only when `count_documents({}) == 0`, generating random UUIDs and inserting complete arrays (`512–533`). This is not deterministic reconciliation: an empty or partially corrupted collection is populated, but an existing collection with stale/mock/incomplete records is silently left untouched. There is no environment/database identity check inside the function, no transaction across collections, lock, unique-index assertion, canonical-ID mapping, version, provenance, rollback, cleanup or post-seed validation. Because `server.py` invokes it at startup only when `NODE_ENV=test` and `ALLOW_TEST_SEED=true`, the caller provides an explicit gate, but the seed module itself is importable/reusable and carries data that could be mistaken for production truth (`server.py:247–255`).

The seed creates no test-user account lifecycle, source snapshot, fixture namespace, tenant isolation or exclusion from public discovery. It does not mark records as test-only, synthetic, pending review or non-indexable. Random IDs make references non-reproducible across runs, while hardcoded prices/ratings/availability can become stale and diverge from the canonical NestJS/catalog contracts. No product code was changed, the seed was not executed, and no tests/builds were run during this semantic read.
