# Phase 0B semantic evidence — SeoSearchModule

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Member read in full:** `src/modules/seo-search/seo-search.module.ts:2–389` (including the previously truncated ranges 228–389)

The module defines `SeoSearchService` and public `SeoSearchController` routes for SEO metadata, sitemap/robots, site structured data, `llms.txt`, image sitemap, global search and recommendations (`19–21,244–388`). Metadata loads category as a synthetic object and medicine/article/provider records by unvalidated type/id, then emits canonical URL, title, description, OG/Twitter, JSON-LD, breadcrumbs, robots index/follow and sitemap fields (`23–51`). Medicine JSON-LD uses Product/Offer with SAR and availability derived from record fields; article uses Article and organization author; default entities use Physician or MedicalBusiness (`66–105`).

The sitemap reads non-deleted medicines only, limits to 2,000, derives slug and falls back to a fixed `2026-07-01` lastmod, and emits XML (`109–119`). Global search rejects terms shorter than two characters, queries medicines/providers/home-care services with regex interpolation and per-collection limits, calculates total and a heuristic intent/ranking response (`121–168`). Medicine recommendations use active ingredient, strength, category, brand and popularity candidate queries, weighted scores and a client-visible `ai_rank_ready` marker (`177–225`). Doctor recommendations use same specialty and city with rating ordering (`228–241`). Public controller routes expose sitemap/robots/site schemas/metadata/hreflang/llms/image sitemap/search/recommendation endpoints (`249–381`).

Findings: `type` and `id` are not runtime allowlisted/validated before entity selection or canonical construction (`23–50,304–307`); category metadata is synthetic and can create indexable content without a real catalog entity (`47–50,89–95`). Metadata returns `robots:index,follow` without checking publication/review/deleted/consent state, and article/provider JSON-LD lacks complete provenance/availability/lifecycle safeguards (`23–44,81–105`). Product Offer uses `e.price` and an availability fallback that may represent missing availability as InStock; no currency/decimal/stock authority or price-date truthfulness is established (`68–77`). XML escaping is incomplete for loc/image URLs and service/slug values; image sitemap escapes only ampersand/less-than in title (`109–119,352–362`).

Sitemap breadth is capped at 2,000 without sitemap index/pagination, includes no articles/providers/categories and may emit fixed stale lastmod; image sitemap caps at 1,500, has public CDN fallback, no URL validation and no error handling (`109–119,348–363`). Robots explicitly allows all `/s/` pages and sitemap while public SEO endpoints and `llms.txt` expose operational/catalog claims (`257–262,326–345`). `llms.txt` contains hard-coded claims such as 21,052 products, 21,000+ catalog and public endpoint semantics that require source reconciliation (`331–345`).

Search accepts `limit` via `parseInt` with no finite/range clamp in the controller; service regexes user input directly, and no escaping/regex abuse, pagination cursor, timeout, ranking provenance, cross-tenant filter, sensitive-field policy or cache consistency is shown (`121–168,365–380`). Search projections expose price, rating, city, manufacturer and media publicly without publication/verification/privacy policy (`125–133`). Recommendation limits and IDs are similarly unvalidated; medicine recommendations expose recommendation scores/reasons and `ai_rank_ready` without model governance or stale-price/availability safeguards (`177–225,371–380`).

All routes are public; there is no rate limit, query abuse control, observability redaction, audit, cache invalidation, 404/410 lifecycle, IndexNow delivery, structured-data validation, hreflang completeness or multilingual canonical consistency (`244–381`). Site Organization/MedicalBusiness/FAQ schemas are static and claims may diverge from actual services, licensing, support languages and inventory (`264–302`). No code was changed and no build/test/application operation was performed during this read.
