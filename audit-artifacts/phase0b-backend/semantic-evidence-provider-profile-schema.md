**Audit judgment:** The model mixes provider identity, licensing/KYC, public discovery eligibility, medical review, bank payout data, prices/capabilities, roster/contact PII, operational schedules, registration wizard snapshots and approval metadata in one broad document. Sensitive license/national/tax/bank/signature/document URL data has no declared encryption, field-level projection, redaction, retention or access policy. `user_id` is only indexed (not unique/canonically referenced), while `account_id`/slug unique-sparse do not enforce provider ownership or tenant boundaries. Public/indexing eligibility and medical/licensing status are mutable booleans/strings without an explicit transition guard, actor authorization, evidence linkage or invariant requiring verified status before publication/indexing. Multiple money/commission/radius/duration/rating fields lack non-negative/range/currency/precision validation and rating aggregates can be written without source/version or atomic review aggregation. `lab_roster`, `radiology_roster`, `nursing_roster`, `registration_steps`, schedules and several object arrays use `any` or weak shapes, allowing schema drift and potentially exposing unreviewed/raw wizard data. Embedded doctor roster contains email and prices without a clear projection or canonical doctor reference. `pre('save')` slug generation is not an atomic uniqueness/rename lifecycle; update-based writes can bypass it and collision errors are not handled here. No optimistic concurrency, immutable audit trail, field ownership, consent, or deletion/retention behavior is declared.

No product code was changed and no tests were executed during this semantic read.
