# Phase 0B semantic evidence — DeviceTrustModule

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Member read in full:** `src/modules/device-trust/device-trust.module.ts:1–166`

The module defines DeviceTrustService, DeviceTrustController and DeviceTrustModule (`21–27,127–165`). `challenge` creates a 24-byte base64url nonce, stores `attest:{platform}:{nonce}` in Redis for 600 seconds with the user id or guest, and returns nonce/platform/TTL (`29–37`). `verify` requires platform/token/nonce, retrieves and deletes the challenge when a Redis client exists, dispatches Android to Play Integrity and iOS to App Attest, and on trusted verdict stores `trusted:{userId}:{platform}` for 30 days and writes a security event (`39–68`).

Android verification is active only when `PLAY_INTEGRITY_SERVICE_ACCOUNT_JSON` exists; it calls Google decodeIntegrityToken and checks PLAY_RECOGNIZED, MEETS_DEVICE_INTEGRITY and configured package name (`71–106`). Missing configuration explicitly returns untrusted with `play_integrity_not_configured` and `signals.placeholder=true` (`73–76`). iOS verification checks three APNS environment values but only returns `app_attest_pending_keys` when configured; actual CBOR/assertion/certificate validation is not implemented (`109–117`). `isTrusted` reads Redis and fails closed without client/user id (`119–124`). Authenticated challenge/verify/status routes use JwtAuthGuard, while `challenge-guest` is Public and creates a guest challenge (`131–156`).

Critical gaps: platform is typed but not runtime-allowlisted before Redis keying/dispatch, and challenge ownership is retrieved but never compared with the verifying user id (`40–51`). If Redis is unavailable, challenge existence/one-time replay protection is bypassed (`45–51`). Guest challenges can be created publicly and are not shown to be bound to a device/session or prevented from being used in an authenticated verification (`137–140`). Nonce is not bound to package/app instance/device key, request context or user, and token freshness, audience, nonce claim and replay are not validated in this module (`31–68`). Android checks selected verdicts but does not test token request-details nonce/your server nonce binding, cloud project, licensing policy or complete verdict semantics (`89–102`). iOS App Attest is an explicit placeholder/pending implementation even when configuration is present (`109–116`).

The trusted Redis key is a boolean per user/platform, with no device identity, attestation version, revocation, logout/session binding, last-seen, risk reason or multi-device model (`61–66,119–124`). `signals` are `any` and may expose provider/device/licensing information; security-event persistence has no failure handling or PII minimization (`53–68`). Controller status returns user_id and trust flags but has no response DTO or rate limit (`149–156`). No HTTP integration, role/tenant boundary, nonce replay, expired challenge, Redis failure, provider timeout, malformed platform/token, App Attest valid/invalid, revocation, rotation, notification or sensitive-endpoint enforcement evidence exists. No code was changed and no build/test/application operation was performed during this read.
