The file defines LabService, LabBookingState/transitions, LabBooking and LabSample (`7–150`). LabService stores multilingual catalog names/descriptions, short code/category/sample type, price/old_price, fasting, home/facility support, turnaround, preparation text, package/included service IDs, popularity, active/unavailable/deleted, public/indexing eligibility, medical review status/time/provenance/version, cash/insurance/home/in-lab availability, notes, reference ranges, image and icon (`7–55`). A text and category/popularity index is declared (`52–54`).

Medical/public/indexing eligibility, active/unavailable/deleted and cash/insurance/home/in-lab availability are independent booleans/statuses with no reviewer actor, transition, evidence, expiry, source or cross-field publication invariant (`29–47`). `version` exists but no optimistic-concurrency semantics is declared (`40`). Image/icon are raw strings without secure media controls (`49–50`).

Payment and insurance fields lack method/status/currency/authorization/copay consistency, preauthorization, refund or settlement source invariants (`110–116`).

Address/GPS have no bounds, precision, freshness, consent or access/retention policy (`103,132`).

LabSample has unique/indexed ID, order/patient IDs, unique barcode, free-form tests, enum stage, assigned_to and notes (`138–149`), but no order/patient match, test catalog/specimen identity, barcode format/issuance, chain-of-custody, collection/receipt/processing timestamps, result linkage, lab/tenant boundary or stage actor/CAS (`140–147`). No idempotency, duplicate booking/order/sample prevention, notification delivery, retention/legal hold, soft delete, PII/PHI projection or live catalog/booking/insurance/sample runtime evidence is established.
