# Phase 0B semantic evidence — Provider onboarding and contract PDF

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Members read in full:**
- `src/modules/provider-onboarding/contract-pdf.service.ts:2–223`
- `src/modules/provider-onboarding/provider-onboarding.module.ts:2–501`

Provider onboarding is a three-step wizard for provider types, with public `POST /provider-onboarding/start`, authenticated step2/step3/submit/profile/progress/contract routes, admin contract routes, and public `GET /search/providers` (`provider-onboarding.module.ts:13–20,432–501`). `start` accepts phone/password/name/email/type publicly, creates an active user with a role derived from type, and creates or resets a pending provider profile (`45–78`).

Step2 and step3 copy allowlisted top-level fields but also append almost every submitted field into `registration_steps`, excluding only keys matching pass/secret/token and local file/content URIs; no visible field-size/depth/array bounds or PHI/financial redaction is applied (`80–114,117–185`). Profile and progress endpoints return broad provider documents (`187–193,381–385`). Submit marks the profile completed/pending, accepts signer/signature/location/full_data, mirrors moderation state and generates/stores a base64 PDF, but swallows mirror/contract generation failures so submission can succeed without a review queue or contract (`195–223`).

Contract generation loads signature data from data URLs, storage object IDs or arbitrary HTTP(S) URLs; external fetches have no visible host allowlist, size limit, timeout or content-type restriction (`79–121`). It uses HMAC-independent SHA-256 of generated bytes plus profile ID, includes license/email/phone in PDF, uses a manual Arabic word reversal for bidi, and returns the PDF/sha (`124–221`). Stored contracts are base64 in Mongo; provider visibility is defaulted true on insert, while admin visibility endpoint can revoke it (`249–269,282–317`). Admin contract read returns raw base64 and signer fields; authorization is manual role comparison (`460–473`).

Moderation mirror copies provider email/phone/password hash, marks email verified, sets pending approval and writes status history; resubmission behavior preserves approved/suspended status but overwrites onboarding metadata (`325–379`). Unified search interpolates service query directly into a regex over multiple provider fields and returns broad provider documents excluding only license documents (`387–428`).

No product code was changed and no tests/builds were executed during this semantic read.

## Findings candidates

The read supports: public account/provisioning abuse, raw registration snapshot PII, contract generation SSRF/resource risks, contract visibility and base64 disclosure, swallowed critical failures, moderation mirror trust gaps, regex search abuse and broad provider document exposure.
