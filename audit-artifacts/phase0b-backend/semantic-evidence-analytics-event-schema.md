# Phase 0B semantic evidence — analytics-event.schema.ts

**Archive member:** `src/schemas/analytics-event.schema.ts`  
**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`  
**Read range:** lines 2–17; full 17-line member covered.

Lines 2–5 import Document/uuid and define a timestamped `analytics_events` collection. Line 7 defines an id generated by uuid. Line 8 stores optional indexed user_id. Lines 9–10 require indexed free-form event_type and domain. Line 11 stores arbitrary metadata Object. Line 12 stores optional indexed session_id. Lines 13–14 store optional ip_address and user_agent. Lines 16–17 define the document type and create the schema.

**Audit judgment:** Indexed event_type/domain and optional user/session attribution are useful analytics primitives. However event_type and domain are free-form, metadata is `Record<string, any>` with no size/key/value allowlist, and IP/user-agent may be personal data. There is no consent/purpose field, retention/expiry/TTL index, anonymization/hash policy, tenant/source/client authenticity, request/event idempotency or deduplication key, sequence/correlation ID, or projection/redaction contract. A generated id alone does not prevent replayed analytics events or forged attribution.

No product code was changed and no tests were executed during this semantic read.
