# Phase 0B semantic evidence — Unified provider jobs module

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Member read in full:** `src/modules/provider-jobs/provider-jobs.module.ts:1–289` (read in three ranges due to file size)

`ProviderJobsService` unifies pharmacy, lab, radiology, nursing and consultation records behind one provider inbox. It uses typed models for some booking entities but `Model<any>` for appointments, provider profiles, users and attachments, and accepts `any` principals/bodies (`27–36,56–80,188–228`). Capability selection treats `admin` and generic `provider` as all domains, maps roles to domains, then lets a provider profile `capabilities` array override defaults; lookup is by `user_id` only and errors are swallowed (`55–80`). This creates a fail-open/under-specified capability policy and no evidence of tenant/facility/credential/assignment scope.

`queue` queries each domain by different provider fields, maps records into a shared object and enriches it with patient name/phone, age, gender, blood type, allergies, chronic diseases and attachment count (`82–174`). The returned queue therefore includes sensitive clinical/PII fields without a role-specific minimum-necessary projection, consent check, patient relationship check, pagination cursor or event freshness contract. Each query is bounded at 50 but the combined response can reach 250 before enrichment; filters are unvalidated. The mapping uses fallback numeric total `0` and payment defaults (`121–140`), which can fabricate/obscure commercial truth when source fields are absent.

`findEntity` scopes by provider-related fields but different domains use different ownership fields and do not consistently require non-deleted/active/assigned state (`177–185`). Generic actions accept/reject/start/complete map universal states to domain literals and delegate to `WorkflowEngineService`, but include an unused `Model` selection inside mutation, set actor role hardcoded to `'provider'` even for pharmacy/lab/admin callers, append state history and save without visible idempotency/compare-and-set in this member (`188–227`). The module permits roles including admin but actor metadata remains provider; legal transition checks are delegated externally and not established here.

`updateInsurance` accepts arbitrary `insuranceDetails`, spreads it into stored `insurance_details`, permits client-supplied approvalStatus, and stamps submitted/approved metadata based on that value; no DTO, insurer/claim validation, patient consent, attachment verification, amount/source, idempotency or audit decorator is visible (`228–250`). Controller routes are all authenticated by JwtAuthGuard but use `any`, expose capability output, accept arbitrary reasons/bodies and have no idempotency contract (`254–267`). Module wiring imports WorkflowEngine and eight operational models but no visible rate limit, serializer/redactor, policy guard, transaction/outbox or schema/index readiness checks (`270–288`). No product code was changed and no tests/builds were executed during this semantic read.
