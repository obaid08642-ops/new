# Phase 0B semantic evidence — Doctors schemas

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Member read in full:** `src/modules/doctors/doctors.schemas.ts:1–118`

The `Doctor` schema stores provider identity, specialty, languages, photo/biography, ratings, consultation fees, service enablement, insurance list, clinic location/images/tags, accepting/online flags, schedule, blocked dates, capacity, deletion and publication status (`5–42`). Several commercially or publicly meaningful fields use unconstrained primitives and defaults: `rating`, `reviews_count`, and multiple fee fields default to zero or a hardcoded consultation fee; `insurance_supported`, `clinic_location`, schedules, blocked dates and tags use arrays/objects without visible nested validation (`14–39`). `status` is a free string despite a comment describing a three-value enum, and `is_online`, `is_accepting`, and `clinic_enabled` default true (`23–39`). A save hook builds a slug from mutable names and UUID, but does not prove uniqueness at the application level or protect slug history (`44–49`).

`DoctorAppointment` stores both patient identifiers and direct patient PII (`57–73`), unconstrained `type`/payment/insurance strings despite TypeScript aliases, fee default zero, arbitrary documents/address/state history arrays, and no visible unique compound slot/doctor conflict index; only doctor/time and patient/time indexes exist (`52–77`). This schema does not itself enforce ownership, payment truth, insurance state, state transition, PII projection or idempotency. `DoctorChatMessage` stores sender role/account, free text and arbitrary attachment object with no content/attachment validation or appointment participant constraint (`79–88`). `ConsultationNote` stores diagnosis, notes, follow-up instructions and prescriptions as free strings/array objects with no clinical validation, signing/finalization, amendment audit or access boundary (`90–101`). `NotificationItem` stores recipient identity, role, body/entity/deep link and read flag; type, role, deep link and content have no enum/safety/URL policy, and no deduplication/idempotency is visible beyond generated ID (`103–117`). No product code was changed and no tests/builds were executed during this semantic read.
