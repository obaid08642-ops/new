# Phase 0B semantic evidence — MaternityService spec

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Member read in full:** `src/modules/maternity/maternity.service.spec.ts:1–44`

The spec uses an in-memory stored document and a mocked model with only findOne/create (`4–13`). It verifies an unconfigured patient profile returns profile_ready=false and tracking_mode=null without inventing pregnancy, due date, cycle length or checkups (`15–19`). It verifies pregnancy tracking requires a user-entered LMP date, creates a patient-linked profile and computes a current week/estimate (`21–29`). It verifies cycle tracking requires a last-period date and explicit cycle length (`31–36`). It verifies pregnancy-only kick/contraction logs are rejected for cycle tracking and the selected values are rejected (`38–43`).

The spec is local/mock-bound and directly supplies patient_id; HTTP authentication, patient state, provider/family delegation, tenant and live persistence are unproven (`6–13,15–43`). Pregnancy tests do not cover date validity/future dates, timezone/DST, gestational-age bounds, due-date calculation accuracy, multiple pregnancies, miscarriage/postpartum transitions, clinician confirmation or uncertainty disclosure (`21–29`). Cycle tests do not cover cycle-length bounds/type, irregular cycles, date ranges, ovulation/period estimates or mode transitions (`31–36`). Kick/contraction tests cover only wrong-mode/impossible selected values; they do not cover valid logs, duration/frequency/intensity units, chronology, duplicates, escalation thresholds or clinical safety (`38–43`). No checkup, infant-growth, symptom, appointment or notification behavior is covered despite document fields for those arrays (`5`). No consent/PHI minimization, access audit, retention/deletion, rate limit, idempotency, transaction, event/cache or live clinical-provider evidence exists. No code was changed and no build/test/application operation was performed during this read.
