# Phase 0B semantic evidence — Insurance logo asset publisher

**Baseline:** `main @ 22526bedb77a3d8148219036367e4714f401aecc`

**Member read in full:** `scripts/publish-insurance-logo-assets.ts:1–52`

The script documents a default dry-run and an `--apply` mode intended to upload approved insurance logo assets to S3 and link them in Mongo (`1–11,18`). It loads a local `manifest.json`, filters companies by `logo_status === 'official_source_collected'`, and stores the manifest as untyped JSON; each company is typed `any` (`18–22`). Asset paths are reduced with `path.basename` and read from the local logo root, then SHA-256 is compared to the manifest hash (`24–29`). This prevents directory traversal outside the basename target and detects content mismatch, but it does not validate file type/dimensions, source URL authenticity, manifest signature/version, company identity uniqueness, duplicate assets or complete expected-catalog reconciliation.

`--apply` checks six required environment variables, but does not require a production-safe target identity, approved release/operator token, S3 bucket/account assertion, Mongo database assertion, dry-run artifact approval or immutable change record (`32–41`). It creates an S3 client with `S3_REGION || 'auto'`, `forcePathStyle: true`, uploads each asset with a deterministic key, and overwrites the object without visible conditional versioning, object existence/metadata verification or rollback (`39–46`). It then performs an unconditional Mongo `updateOne` by company code, without checking that the insurer exists uniquely, that the current logo state is expected, or that the URL/hash/source update is coupled transactionally to the object upload (`42–46`). Partial failure can leave an uploaded object without a database link or a database link pointing to an unverified/unavailable object.

The script updates `logo_url`, `logo_source_url`, `logo_sha256` and `logo_verified_at` but does not update a content/version/status provenance record, operator/approval identity, public-cache invalidation, accessibility metadata, asset lifecycle, deletion/orphan cleanup or audit trail (`43–49`). `logo_verified_at` is generated at runtime and is not tied to a source review date. Mongo disconnect is handled on success and attempted in the catch, but S3 client/resource cleanup and compensating rollback are absent (`48–51`). The script was not executed; no product code was changed and no tests/builds were run during this semantic read.
