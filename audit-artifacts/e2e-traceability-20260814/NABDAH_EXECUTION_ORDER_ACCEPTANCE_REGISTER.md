# سجل قبول أمر المعالجة الشامل — منصة نبض

**المصدر:** الأمر المرفق `pasted_content_4.txt`، المقروء كاملاً في 14 أغسطس 2026.
**حدود التنفيذ:** فرع إصلاح معزول فقط؛ لا نشر، ولا قاعدة بيانات إنتاج، ولا OTP أو دفع أو بيانات عملاء حقيقية.
**قاعدة الحالة:** لا تعني `CLOSED` نجاح build أو اختبار وحدة منفرد. لا تستخدم `NOT VERIFIED` إلا لمانع خارجي محدد.

> **الحكم الأولي المثبت:** لم يُنفذ الأمر كاملاً بعد، و**Phase 1 مفتوحة**. نُفذت معالجة مصدرية مهمة لبنود الهوية والمسارات وبعض تدفقات المريض/المزوّد، لكن ما زالت توجد فجوات تشغيلية وأمنية وعقدية، كما لا توجد بيئة staging للـE2E المحكوم ولا مزود دفع/اتصال حي معزول. يبدأ هذا السجل من الحالة الحالية ولا يعيد التدقيق من الصفر.

## سلم الحالات

| الحالة | المعنى التنفيذي |
|---|---|
| `CLOSED-LOCAL` | تغيّر المصدر، وتمت بوابة محلية مناسبة، ويبقى إثبات النشر عند الحاجة |
| `PARTIAL` | عولج جزء أو حُذفت المحاكاة، لكن التكامل الحقيقي أو الاختبار أو حدود الدور غير مكتملة |
| `OPEN-SOURCE` | يمكن ويجب إصلاحه من المصدر الحالي |
| `EXTERNAL-BLOCKER` | يحتاج staging أو مزوداً أو عقداً غير متاح؛ يذكر السبب والاختبار المعلق |
| `NOT-APPLICABLE` | عنصر تصميمي/اختباري ليس workflow إنتاجياً بعد التحقق |

## أولويات التنفيذ المحلي التالية

1. إزالة أو تأمين زرع/seed ومسارات demo وfallbacks الإنتاجية، وإصلاح التفويض والملكية القابلة للتحقق في الخلفية.
2. توحيد إعدادات runtime ومنع `localhost` و`dummy` ونجاح محلي في builds الإنتاجية للمريض والمزوّد والإدارة.
3. استبدال أو إخفاء CTAs التي لا تملك عقداً خادمياً حقيقياً، بدلاً من محاكاة حالة نجاح أو بيانات طبية/مالية.
4. بناء اختبارات سلبية وcontract/unit للتغييرات، وتشغيل regression محلي للمكونات المتأثرة.
5. تجهيز contract catalog وOpenAPI من الخادم، ثم إيقاف العناصر التي لا يمكن توصيلها بلا عقد أو تنفيذها عند وضوح النموذج في المصدر.

## موانع لا يمكن تجاوزها محلياً

| المانع | لماذا لا يحل من المصدر وحده | الاختبار المعلق |
|---|---|---|
| staging مستقل للفرع | لا يصح اختبار فرع جديد على API إنتاجي قديم، ولا توجد بيئة منشورة معزولة | lifecycle كامل وBOLA وواجهات العملاء الحية |
| payment sandbox ومزود webhook | التوقيع والمعاملة والاسترداد والتسوية تعتمد مزوداً وأسرار sandbox | payment/refund/webhook replay/duplicate/reconciliation |
| LiveKit وPush sandbox | room tokens والأحداث والتنبيهات تعتمد مفاتيح وخدمات تشغيلية | call/chat/push delivery/reconnect/missed-call |
| عقود صيدلية التأمين والعروض والتوصيل | لا يوجد نموذج خادمي مخزن متفق عليه حالياً لبعض العمليات | broadcast/offers/select/insurance/delivery end-to-end |

## قواعد التحديث

يحدّث هذا السجل مع كل commit: المعرف، الحالة، الملفات المعدلة، الاختبار المحلي، والاختبار المنشور المعلق. لا تتحول حالة أي بند إلى `CLOSED-LOCAL` إلا مع تغيير مصدر ودليل تحقق مناسب، ولا إلى جاهز للإنتاج قبل بوابات staging في `EO-15`.
