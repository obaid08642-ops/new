# Patient Mobile: Payment processing and saved cards — partial manual review

## Scope boundary

This is an evidence-first **partial** wave covering nine reviewed payment/wallet routes listed below. It does not review or close the remaining payments, wallet transaction history or order routes. No product source, build, runtime test, deployment, merge or live payment action was performed.

| Reviewed source | Scope |
|---|---|
| `app/payments/processing.tsx` | Hosted checkout/WebView/browser hand-off, status polling, wallet top-up confirmation and success/failure routing |
| `app/payments/success.tsx` | Generic payment-success receipt and downstream hand-off |
| `app/payments/failed.tsx` | Generic payment-failure screen |
| `app/payments/failure.tsx` | Duplicate generic payment-failure screen |
| `app/wallet/cards.tsx` | Saved-card list/default/delete and add-card CTA |
| `app/wallet/topup.tsx` | Wallet top-up intent creation |
| `app/wallet/transfer.tsx` | Wallet transfer entry |
| `app/wallet/hub.tsx` | Wallet balance, cards, spending and activity hub |
| `app/wallet/transactions.tsx` | Wallet transaction-history list and local filtering |
| `app/orders/index.tsx` | Cross-domain order/booking center |

## Conclusion

The eleven reviewed financial and order-center sources cannot support a production claim. The processor has a real-looking polling path but remains driven by route parameters and client endpoint heuristics pending backend/ledger reconciliation. Saved-card entry contains hard-coded full-card data that directly contradicts its own security statement; transfer lacks a verified beneficiary and ledger-safe contract; and the wallet hub contains an undefined runtime symbol plus raw-PAN collection. Only these eleven routes should be marked reviewed after the tracker is updated; all other financial routes remain unreviewed.
