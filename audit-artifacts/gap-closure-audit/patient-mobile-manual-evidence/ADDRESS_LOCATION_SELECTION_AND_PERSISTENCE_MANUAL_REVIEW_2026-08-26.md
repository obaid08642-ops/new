# Patient Mobile: Address / Location selection and persistence — manual semantic review

## Scope and review boundary

This read-only artifact covers the two route candidates that form the mobile address-selection dependency and the local selection helper they call. The review establishes only static client behavior. It does **not** establish address ownership, server validation, serviceability/geofence eligibility, delivery/provider allocation, PHI exposure controls, or a booking/order DTO consuming an address ID. Those matters require backend and service-specific reconciliation.

| Reviewed source | Scope |
|---|---|
| `app/delivery/address-select.tsx` | Saved-address selection screen and hand-off to map picker |
| `app/shared/location-picker.tsx` | Saved, GPS/map and new-address modes; address-create CTA |
| `src/utils/selectedAddress.ts` | Local selection persistence and fallback resolution helper |

## Review conclusion

The mobile address surfaces have real saved-address reads, an actual operating-system location request, reverse geocoding, and a create mutation. They remain **only an address-selection dependency**. They do not prove a valid address is owned, deliverable, serviceable, persisted authoritatively, or bound to any downstream pharmacy, consultation, diagnostics, nursing, or delivery request. The two route candidates can be marked as manually reviewed with findings recorded; the helper is supporting evidence rather than a separate inventory row.
