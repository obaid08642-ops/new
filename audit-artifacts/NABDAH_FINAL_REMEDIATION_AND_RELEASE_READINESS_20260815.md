## الحكم التنفيذي

أُنجزت المعالجة المصدرية المعزولة للمخاطر التي أمكن إثباتها من الكود والعقود المتصلة به، وحُفظت في **أربعة أرشيفات تطبيق كاملة** على فرع GitHub مستقل. أُغلقت بوابات البناء والاختبارات المتاحة بعد كل مرحلة. ومع ذلك، فإن قرار النشر أو إرسال التطبيقات للمتاجر هو **غير جاهز حالياً**؛ إذ تبقى متطلبات تشغيلية وعقود حساسة لا يمكن إثباتها دون staging منفصل وبيانات اختبار وخدمات خارجية مضبوطة.

| مجال القرار | الحكم | السبب المختصر |
|---|---|---|
| سلامة فرع المصدر | مقبول للمراجعة | الإصلاحات على `manus/on-live-reconciliation` فقط؛ لم يُعدّل `main` |
| بناء المكونات واختباراتها المحلية | ناجح ضمن البوابات المتاحة | backend وExpo للمريض/المزوّد وNext للإدارة اجتازت البوابات المسجلة |
| البيانات الوهمية في المسارات المفحوصة | عولجت أو حُجبت بصدق | أزيلت القيم المركبة في التحاليل والصيدلية وQR والتتبع والتهيئة، أو حُجبت الميزة عند غياب عقد حقيقي |
| أمن المصدر | تحسن جوهرياً | OTP وseed وBOLA وCORS/JWT والإديمبوتنسي وملف المريض عولجت في النطاق المثبت |
| الإنتاج والمتاجر | **غير جاهز** | يلزم staging وE2E ودوران اعتماد R2 ومراجعة lockfiles وعقود consent/QR/location/error codes ومراجعة لغوية بشرية |

## سجل المعالجة المنفذة

### الأساس وPhase 1–1.5

عولجت حواجز البناء الأولية في لوحة الإدارة وتخزين Redux المشفر واختبار Animated للمزوّد. ثم أُغلقت مشاكل OTP والـseed والوصول إلى عينات المختبر. صار OTP مجزأً ومحدوداً زمنياً ومفصولاً بمفاتيح مستقلة، كما حُصرت عمليات seed في بيئات الاختبار الصريحة فقط. أزيلت بيانات اعتماد R2 المضمنة من المصدر، لكن دورانها خارج Git ما زال مطلوباً قبل أي نشر. [1]

أُعيد تصميم idempotency لمسار الدفع المستخدم في المصدر بحيث يكون المفتاح محصوراً بالمستخدم والطريقة والمسار، مع بصمة حمولة وقفل Redis لمنع السباق. لا يعني ذلك أن كل mutation مالي أصبح idempotent؛ أي توسعة مستقبلية يجب أن تُراجع endpoint-by-endpoint. [1]

### Phase 2 — التهيئة والشبكة

أضيف تحقق إنتاجي مركزي لـMongo وRedis وJWT وCORS، وأزيلت الأسرار التطويرية وفوالب localhost و`dummy-project-id` من المواضع المثبتة. توحدت الإدارة حول API base مركزي، كما صارت بوابات WebSocket تستخدم allow-list للأصول وتفشل بأمان عند غياب إعداد الإنتاج. [1]

| الحالة المعالجة | أثرها |
|---|---|
| متغيرات إنتاج ناقصة | بدء backend يفشل بأمان بدلاً من الاعتماد على fallback |
| JWT dev secret أو handshake غير موثق | لا يسمح للـgateway بقبول هوية مستخدم مزعومة من العميل |
| localhost في تطبيقات العميل والإدارة | لا يتحول نشر الإنتاج إلى service محلي أو origin خاطئ |
| Push project ID افتراضي | لا يصدر token وهمي عندما لا تتوفر تهيئة Expo الفعلية |

### Phase 3–4 — الحجز والهوية والصيدلية

أزيلت أسعار ومزودون وفتحات ومراجع نجاح مصطنعة من حجز التحاليل، وربطت اختيارات المختبر بمعرف حساب مزود حقيقي وبقيم backend المتاحة. تحولت شاشات الصيدلية من إنشاء طلبات أو دفعات أو وصفات أو معرفات محلية إلى مسارات خادم حية، مع إبقاء السعر والتوفر والـdispatch والتأمين في الخادم حيث يثبت العقد. [1]

كما استُبدل QR الذي كان يتضمن معلومات صحية مباشرة برمز JWT قصير العمر لا يحمل بيانات طبية. وعندما تبين غياب verifier وعقد موافقة للمسح، لم تُنشأ واجهة وهمية بديلة؛ حُجبت الواجهة بوضوح إلى حين تصميم العقد. تتبع الطوارئ يعرض البيانات التي يعيدها الخادم فقط ولا يرسم route أو ETA غير مصرح به. [1]

### Phase 5 — التوطين للغات الست

فُحصت 493 ملفاً في تطبيق المريض، وحدد الجرد 1,478 نصاً عربياً ساكناً مرشحاً. أضيف قاموس يتضمن 1,445 عبارة غير مغطاة للغات **العربية والإنجليزية والأردية والهندية والبنغالية والفلبينية**؛ وتحوّلت نصوص `Text` المباشرة وتنبيهات `Alert` في routes إلى بوابات ترجمة مركزية. كما أزيلت بيانات runtime config الثابتة من AppContext. [1]

> نجاح التغطية البنيوية لا يحل محل مراجعة مترجم طبي أصلي أو اختبار الشكل والـRTL على أجهزة iOS وAndroid. محتوى API وSDKs ورسائل backend الخام ليس مؤكداً بأنه مترجم.

### Phase 6 — العقود الحساسة

يعيد endpoint runtime config الآن حقولاً مضبوطة صراحة من متغيرات البيئة فقط، ولا يختلق API URL أو تسعيراً أو بيانات تواصل. وأغلق endpoint عرض الملف الطبي للمزوّد بفشل آمن بسبب غياب علاقة رعاية وموافقة مدققة؛ كان الوصول بالمُعرّف وحده يمثل BOLA لمعلومات صحية حساسة. [1]

| العقد الناقص | السلوك الحالي الآمن | ما يلزم قبل تمكينه |
|---|---|---|
| ملف طبي للمزوّد | 403 fail-closed | موافقة grant/revoke، scope، علاقة علاجية، audit، واجهة للمريض |
| QR صحي | حالة عدم إتاحة صادقة | verifier، role checks، consent، expiry/revocation، audit، E2E |
| مسار طوارئ مرسوم | لا route أو ETA مصطنع | consent location، retention، schema نقاط، directions service |
| أخطاء API مترجمة | حواجز محلية فقط | error code registry وHTTP transitions وowner للعقود |

### استئناف ما بعد Phase 7 — مراجعة إدارة موظفي المنشأة

كشفت المطابقة التفصيلية بعد Phase 7 أن إصلاح إنشاء موظف المنشأة لم يكن كافياً وحده: بقيت مؤشرات المنشأة وشاشات الاعتماد تقرأ `/provider/facility/subaccounts` غير المعرّف في المصدر الخلفي، وكان الحذف يعرض toast محلياً، كما كانت بطاقة QR والحفظ والمشاركة الشكلية تعلن نجاحاً بلا عقد. صُححت هذه المواضع في `FacilityDashboard.tsx` باستخدام `/hospital/staff`، و`DELETE /hospital/staff/:id`، وبيانات الخادم أو حالة عدم الإتاحة الصادقة، ثم نجحت بوابة المزوّد 3/3 وتصدير iOS. يلزم اختبار staging لإثبات الملكية والصلاحيات.

## موانع الإطلاق الإلزامية

لا يصدر قرار إنتاج إيجابي قبل إغلاق البنود التالية، وكلها مصممة كي تنفذ في بيئة staging معزولة لا على الإنتاج.

| الأولوية | المانع | قرار القبول |
|---|---|---|
| حرجة | تدوير اعتماد R2 الذي كُشف تاريخياً | تأكيد إداري خارج Git أن المفتاح القديم أُلغي وأن مفاتيح أقل صلاحية ضُبطت |
| حرجة | تهيئة staging الحقيقية | تحقق start-up من Mongo/Redis/JWT/CORS وservice URLs، بلا fallback |
| حرجة | E2E للهوية والصلاحيات والمال | نجاح سيناريوهات الحسابات المعزولة ورفض BOLA/IDOR والدفع غير الصالح |
| حرجة | قفل عقود consent وQR | إما تنفيذ عقد مصادق عليه واختباره، أو بقاء الميزة غير متاحة في إصدار الإنتاج |
| عالية | عدم تطابق lockfiles | مراجعة اعتماديات وتوليد lockfiles نظيفة مع scan أمني وبناء متكرر |
| عالية | التوطين الطبي | مراجعة بشرية للغات الخمس غير العربية واختبار RTL/overflow/accessibility |
| عالية | error codes وruntime config | قائمة error codes وschema منشوران، وحالات الغياب لا تظهر نجاحاً أو قيمة بديلة |
| متوسطة | مسار الطوارئ والموقع | موافقات موقع وسياسة retention وخرائط/Directions بعقد متفق عليه |

## القرار المقترح لفريق التطوير

يوصى بمراجعة الحزم الأربع وسجل المصالحة أولاً، ثم تشغيل خطة E2E في staging. لا يُنصح بدمج الفرع إلى `main` أو بالرفع للمتاجر قبل إغلاق موانع الإطلاق الحرجة. إذا رفض المنتج عقود QR أو ملف المريض للمزوّد أو مسار الموقع في هذه الدورة، يجب أن تبقى هذه الواجهات **غير متاحة بوضوح**؛ لا تعاد واجهات محاكاة أو بيانات افتراضية لإعطاء انطباع مزيف بالاكتمال.
