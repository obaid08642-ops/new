## مراجعة 2026-11-01 والنص النهائي لاتفاقية مقدم الخدمة
قرر المالك نشر الاتفاقية. المراجعة وجدول البنود ومذكرة نموذج الفوترة وما تغيّر في النص النهائي: في `REVIEW_2026-11-01.md` (يبقى فيه التوصية بمراجعة محامٍ سعودي). تُنشر الاتفاقية في `legal_policies` بالمفتاح `provider_agreement` بالسكربت `backend/src/scripts/publish-legal-policy.ts` (تجربة جافة افتراضياً، و`APPLY=yes` للنشر؛ ينسخ الصف القائم احتياطياً أولاً، ويرفض نصاً فيه كلمة مسودة أو فراغ [ ] أو إصداراً لا يعلو المنشور، ويحذف صف المسودة `provider_agreement_draft`). و`REQUIRE_ACCEPTANCE=no` ينشر دون إلزام المزودين الحاليين بالقبول فوراً.

## مكان الحفظ وطريقة النشر
- **المصدر:** هذه الملفات في المستودع، وكل تعديل يمر بطلب دمج (PR) ويبقى له تاريخ.
- **النسخة المعروضة للمستخدم:** تُحفظ في قاعدة البيانات في جدول `legal_policies`. لكل نسخة: رقم الإصدار، وتاريخ السريان، وسجل التغييرات، والنص بكل لغة. يعدّلها الأدمن، وكل تعديل يُسجَّل في سجل التدقيق.
- **التطبيقات والموقع** تقرأ النص من `GET /legal/policy/:key` فقط، ولا يُكتب أي نص قانوني داخل الشاشات.
- **القبول:** يُسجَّل قبول كل مستخدم أو مقدم خدمة لكل نسخة (`/legal/accept/:key`) مع الوقت والجهاز. وعند صدور نسخة جديدة جوهرية يُطلب القبول مرة أخرى.

## النشر
السكربت `backend/src/scripts/publish-legal-policy.ts` ينشر المفاتيح الخمسة (`POLICIES=all`)، وتشغله المهمة `tools/ops/tasks/99p-publish-agreement.sh` بعد النشر. **تنبيه:** ما إن يوجد أي سياسة منشورة، يرفض تسجيل المريض الجديد (التطبيق والموقع) ما لم يكن `patient_terms` و`privacy_policy` منشورين مع اشتراط القبول؛ لذلك ينشرها السكربت معاً ويرفض أي تشغيل يترك هذه الحالة.

## المطلوب قبل النشر (قائمة قديمة، للرجوع)
1. يملأ المالك البيانات الموجودة بين قوسين مربعين [ ]، مثل الاسم التجاري ورقم السجل التجاري والعنوان والبريد.
2. يراجع المحامي النصوص ويعتمدها.
3. تُترجم النسخة المعتمدة إلى اللغات الست (ar, en, ur, hi, bn, fil). وجدول `legal_policies` يحفظ حالياً العربية والإنجليزية فقط، فيلزم توسيعه إلى ست لغات (مهمة في قائمة أوبن كود).
4. يُصدر المالك الإصدار 1.0 من لوحة الأدمن.
