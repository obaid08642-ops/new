# حدود BFF للبيانات الخاصة

تعمل صفحات المريض الخاصة كمكونات خادمية في Next.js. تستخرج الجلسة من cookies ذات `httpOnly` على الخادم، ثم تمرر access token إلى بوابة خادمية داخلية فقط. لا يُدرج التوكن في HTML أو JavaScript أو عنوان URL، ولا تستدعي المتصفحات الخلفية الإنتاجية مباشرة.

| المجال | بوابة الخادم | حماية الإدخال | معالجة الرفض |
|---|---|---|---|
| الطلبات | `callPatientApi` من مكوّن خادمي | UUID لتفاصيل الطلب | `401` دخول؛ `403/404` غير متاح |
| الملف الصحي | `callPatientApi` من مكوّن خادمي | قائمة حقول صريحة فقط | حالة فارغة/رفض/خطأ منفصلة |
| المواعيد | `getPatientAppointments` و`getPatientAppointment` | UUID للمسار؛ لا حقول انتظار ثابتة | `401` دخول؛ `403/404` غير متاح |

يبقى Route Handler في `/api/patient/[...path]` بوابة BFF للنداءات التي تبدأ من المتصفح. أما القراءات التي تبدأ من Server Components فتستخدم البوابة الخادمية نفسها مباشرة، لأن تحويلها إلى طلب HTTP داخلي لا يضيف حماية ويزيد سطح الجلسة والتشغيل. كلا المسارين ينتهيان عند `callPatientApi`، التي تضيف Bearer token على الخادم وحده.
