## Failures (for routing)

1. **`tools/live/j_qa_refund_consultation.py:91`**: "the admin refunds the full amount" returns 400 `no_confirmed_payment_to_refund`.
   - Cause, from the database: the patient's own cancellation of the paid visit already refunded the full 25 SAR. The transaction is `refunded` (`refunded_amount: 25`), and `platformledgerentries` holds one refund of 25 for the order.
   - The refusal is raised at `backend/src/modules/admin/enterprise/orders-console.service.ts:368` (no confirmed payment left to refund). That is the no-double-refund rule working.
   - So this is a conflict in the journey's scenario, not a product fault on its own: the journey expects a second, admin refund after an automatic refund. The owner should decide which scenario the journey is meant to test (a refund-after-cancel test, or a manual refund on a visit the patient did not cancel).
   - Note: this does not test the walk's P0 (`backend/src/modules/care/appointments.service.ts:518`, a cancel after completion still refunds). That case is not in this journey.

2. **#2015 shard 1, `tools/live/j_web_qa_chi.py`**: the CI failure (a second CHI link after reload) **did not reproduce** here. The journey passed 10/10 on the local stack in one run. The cause in CI is not established. The diagnostic commit `4a356285` will show the extra anchor's parent in the CI log when it fails.
