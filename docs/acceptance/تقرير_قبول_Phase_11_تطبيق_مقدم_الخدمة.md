# تقرير قبول Phase 11 — تطبيق مقدم الخدمة

**المشروع:** نَبْض الصحي (Nabdah)  
**النطاق:** تطبيق مقدم الخدمة في `/home/ubuntu/nabdah-phase1-work/provider/NabdProvider/`  
**الحالة:** مكتملة محلياً  
**GitHub:** لم يُنشأ commit أو branch أو push.

## الملخص التنفيذي

استهدف التدقيق مسارات مقدم الخدمة التي يمكن أن تُظهر حالة تشغيلية غير متحققة أو أن تغير حالة سريرية أو مالية محلياً. جرى ربط التوفر في التطبيق بالحالة الخادمية المشتركة، وإزالة مسار تحصيل نقدي محلي من لوحة الطبيب، وإلغاء إنشاء رابط PDF مصطنع لتقرير الأشعة، وتمكين تصدير الويب من دون تعطيل خرائط الهاتف الأصلية.

> **القاعدة المطبقة:** لا تظهر الصيدلية أو مقدم الخدمة «متصلاً» لمجرد فتح التطبيق، ولا يبدأ الطبيب استشارة أو يقفل تحصيل نقدي دون عملية خادمية، ولا يُنشر تقرير أشعة من رابط ملف تم اختلاقه محلياً.

## الإصلاحات المنفذة

| المجال | المشكلة | المعالجة |
|---|---|---|
| حالة مقدم الخدمة | كان نموذج الجلسة يضبط `isOnline: true` افتراضياً بعد تسجيل الدخول. | أصبحت الحالة الابتدائية `false` إلى أن تتغير عبر عقد التوفر الخادمي. |
| تواجد الصيدلية | كانت لوحة الصيدلية تحتفظ بـ`useState(true)` مستقلة عن الخادم. | أصبحت تعتمد `useAuth()` و`toggleOnline()`، فتتوافق مع عقد `/provider/ops/availability/toggle-instant`. |
| قبول طلب نقدي للطبيب | كان زر «تم تحصيل المبلغ نقداً» يعلن قفل الدفع ويبدأ الاستشارة من الواجهة فقط. | أزيل الزر؛ بقي قبول الطلب فقط عبر `/provider/jobs/:type/:id/accept`. |
| فشل تحميل لوحة الطبيب | كان طلب الصف والمواعيد يرسل إشعاراً فقط ولا يفعّل بطاقة إعادة المحاولة. | أصبحت حالة الفشل تتغير فعلياً عبر `setError(true)`. |
| رفع تقرير الأشعة | كانت الشاشة تولّد رابط `https://storage.nabdah.com/reports/{id}.pdf` وتتعامل معه كتقرير مرفوع. | أضيف حقل صريح لرابط HTTPS حقيقي للـPDF الموقّع، مع تحقق واجهة قبل الحفظ وعدم إنشاء أي رابط تلقائياً. |
| بناء الويب | كان تصدير Expo يفشل لأن شاشات التسجيل تستورد `react-native-maps` مباشرة. | أضيفت طبقة `PlatformMap`؛ الهاتف يستخدم الخريطة الأصلية، والويب يستخدم مكوّناً توضيحياً آمناً، مع استبدال الاستيرادات المباشرة. |
| تبعيات الويب | لم يكن `react-dom` و`react-native-web` مسجلين رغم تفعيل web. | أضيفتا إلى تبعيات المشروع، وعاد تصدير web للنجاح. |

## ملاحظة تقنية

تثبيت التبعيات من `package-lock.json` تطلب الخيار `--legacy-peer-deps` بسبب تعارض peer dependency معروف بين حزم LiveKit وReact DOM. لم تُرفع أي تبعية أو تغييرات إلى GitHub، ولم تُغيّر إصدارات React أو Expo الأساسية. بعد اكتمال التثبيت وإضافة تبعيات الويب الناقصة، نجح فحص الأنواع والاختبار والتصدير.
