## الملخص التنفيذي

استبدلت المرحلة السابعة تدفقات التشخيص التوليدي وتحليل صورة البشرة غير المنضبطة بتدفقات **فرز إرشادي محافظ** و**قائمة ملاحظة للبشرة**. لا تعود المنصة إلى نموذج لغوي لتخمين مرض أو اقتراح فحوصات أو علاج؛ بل تحفظ ما يختاره المريض فقط وتعرض مستوى تصعيد واضحاً: طوارئ عند اختيار إشارات إنذار محددة، أو استشارة عند غيابها، من دون أن يعني ذلك استبعاد حالة طبية.

فحص البشرة لم يعد يلتقط أو يرفع أو يحلل صوراً. أصبح قائمة ملاحظات ذاتية تفرض إقرار المستخدم بحدودها، ثم توجّه إلى تقييم سريري عند اختيار تغيرات معروفة بأنها تستحق المراجعة، مثل بقعة جديدة/متغيرة أو نمو/تغير اللون أو الألم/الحكة أو النزف/القشور أو عدم الالتئام لأكثر من أربعة أسابيع. تصف NHS هذه العلامات كأسباب لمراجعة طبيب، مع التنبيه إلى أن الإحالة لا تمثل تشخيصاً.[1]

## ما نُفّذ

| المجال | التنفيذ المقبول |
|---|---|
| فرز الأعراض | `POST /ai/triage` أصبح عقداً منظماً يتطلب وصفاً قصيراً للأعراض وعلامات إنذار من قائمة مغلقة. يعيد `care_level` فقط: `emergency` أو `consultation`. |
| منع التشخيص | أزيلت مطالبة النموذج بـ«تنفيذ فرز طبي» واقتراح التخصصات والتحاليل. النتيجة تحتوي صراحةً على `diagnosis: null` و`treatment: null`. |
| الطوارئ | عند اختيار ألم/ضغط الصدر أو صعوبة التنفس أو إغماء/عدم استجابة أو نزف غزير أو ارتباك جديد أو تحسس شديد أو إصابة شديدة، تعرض الواجهة الاتصال بالطوارئ المحلية فوراً. |
| ملكية البيانات | الفرز يتطلب هوية مريض مصادقاً عليها؛ لا `guest`. تسجل الجلسات تحت `patient_id` فقط، وسجل الفرز يرشح بهوية المريض نفسها. |
| فحص البشرة | `POST /ai/skin-analysis` أصبح قائمة ملاحظات ذاتية تتطلب المنطقة وإقرار حدود الخدمة. يرفض صراحةً `image_base64` لأن تحليل الصور غير متاح حتى تتوفر مراجعة سريرية وخصوصية وتنظيمية مناسبة. |
| خصوصية الصور | أزيلت الكاميرا والمعرض و`ImagePicker` ورفع Base64 من شاشة فحص البشرة. لا تُخزن أو تحلل صورة جلد في هذا التدفق. |
| نتيجة البشرة | تعيد الواجهة `clinical_assessment` عند وجود تغيرات يحددها المستخدم، أو `self_observation` عند عدم اختيارها، مع نص صريح أن عدم الاختيار لا يستبعد حالة جلدية. |
| محادثة التشخيص الحرة | أزيل مسار `POST /ai/triage/chat` من المتحكم. تحولت شاشة `chat-doctor` إلى Redirect صادق نحو الفرز الإرشادي المنظم. |
| اللغات | أضيف قاموس `guided-care.ts` واختبار اكتمال له باللغات العربية والإنجليزية والأردية والهندية والبنغالية والفلبينية. |
| النسخ الاحتياطية | حُفظت ملفات الواجهة والخدمة والمتحكم السابقة في `backups/guided-triage-skin-pre-phase7/`. |

## مبادئ السلامة المطبقة

> **لا يعرض نَبْض اسماً لمرض أو درجة ثقة أو قائمة فحوصات أو علاجاً مقترحاً ضمن هذين المسارين.** لا يمكن أن تكون النتيجة المنخفضة أو عدم وجود إشارات مختارة بمثابة طمأنة طبية أو استبعاد لمرض.

| المبدأ | التطبيق |
|---|---|
| الفرز لا يساوي تشخيصاً | يعتمد مستوى الرعاية على إشارات مختارة مباشرةً من المستخدم، وليس على تنبؤ LLM. |
| التصعيد لا ينتظر | النتيجة ذات إشارات الإنذار تقود إلى اتصال بالطوارئ المحلية، بدلاً من محادثة أو انتظار تحليل. |
| فحص البشرة ليس تحليل صورة | يظهر ذلك في العنوان والإقرار والعقد الخلفي والاستجابة (`image_analysis: false`). |
| لا تسريب أو سجل ضيف | يتطلب العقد هوية المريض ويرفض `guest`، وتكتب السجلات في مجموعات منفصلة تحت `patient_id`. |
| لا نتائج ثابتة | أزيلت حالة الجفاف الافتراضية والنسب والدرجات ومنتجات العناية والتوصيات الدوائية أو التجارية. |
