## التسلسل التجاري المراجع

يمر طلب الصيدلية النقدي من البث إلى العروض المستقلة، ثم اختيار المريض. إذا احتوى العرض بدائل أو نقصاً ينتقل إلى تفاوض حاكم مع محادثات للبنود المتأثرة. يقدم المزود مراجعة نهائية، ولا يمكن إنشاء intent حتى يوافق المريض على hash ومراجعة اللقطة الخادمية. وبعد الدفع الإلكتروني المؤكد أو تسجيل COD المؤهل يصبح الطلب قابلاً للتنفيذ.

أما طلب التأمين فيختار المريض العرض ثم يقبل quote النهائي من دون دفع. تنتج الصيدلية قراراً لكل بند، ويتاح للمريض co-pay أو الدفع الذاتي فقط بعد تسجيل تلك القرارات. لا يقبل أي endpoint مبلغاً أو snapshot أو decision من العميل باعتبارها حقائق مالية.

## نقاط المراجعة المطلوبة

| المجال | ما يجب أن يتحقق منه المراجع المستقل |
|---|---|
| العقود والحالات | عدم وجود انتقال يفتح الدفع قبل قبول final quote، وعدم تجاوز قرار التأمين لكل بند. |
| المال | تطابق `Transaction` مع hash/revision ومبلغ/عملة الـquote، ورفض نتيجة بوابة لا تطابقها. |
| COD | أهلية مسجلة على quote النقدي، والتزام خادمي قابل للتدقيق؛ لا تحقق زائف للدفع. |
| التوافق القديم | endpoint `i-have-all` يرفض ولا يعيد تخصيص أو حجز مخزون تلقائياً. |
| الاختبارات | جميع بوابات CI الخمس ناجحة على رأس كل PR؛ تبقى المراجعة البشرية الإلزامية قائمة. |

## القيود التي تمنع ادعاء الجاهزية

لا تغطي الحزمة تكامل PSP حقيقياً أو توقيع بوابة مثبتاً في بيئة staging، أو معاملات Mongo متعددة المستندات/outbox متيناً، أو تحصيل وتسوية COD مع مزود، أو co-pay صفرياً، أو شاشات Patient Web وMobile الكاملة، أو E2E/الأمن/الأداء. يجب معالجة هذه البنود في PRs مستقلة مع أدلة staging وخطة rollback قبل أي إصدار إنتاجي.

لا يجوز دمج هذه الطلبات من قبل صاحبها: تحمي الفروع المراجعة المستقلة وبوابات الحالة، ولا ينبغي تجاوزها.
