# قرارات الإصدار المقفلة — Patient Production

**الحالة:** معتمد للتنفيذ في `release/patient-production`  
**الإصدار:** 1.0  
**تاريخ السريان:** 27 أغسطس 2026

> لا تُغيَّر هذه القرارات عبر الواجهة أو التعليقات البرمجية. أي تعديل يحتاج Pull Request مستقل، تحديثاً لعقود المجال، واختبارات قبول مرتبطة بالقرار.

| المعرف | القرار المقفل | قاعدة التنفيذ |
|---|---|---|
| PAY-001 | لا توجد محفظة كطريقة دفع للعميل. | تمنع عقود API وواجهات العميل وحراس الحالة قيم `wallet` و`balance` و`wallet_debit` كوسائل دفع. لا تُستخدم أرصدة أو معاملات المحفظة لحساب قيمة الطلب. |
| PAY-002 | الدفع الإلكتروني هو بطاقة أو محفظة رقمية يدعمها مزود البوابة المهيأ. | تشمل Visa وMastercard وApple Pay وGoogle Pay حيث يعلن مزود البوابة والجهاز والبلد دعمها. لا يظهر خيار غير مدعوم ولا تتعامل الواجهة معه كنجاح محلي. |
| PAY-003 | نجاح الدفع يصدر من webhook خادمي فقط. | تتحقق الخدمة من توقيع الحدث، معرف المزود، المبلغ، العملة، حالة العملية، مرجع السعر، ومنع الإعادة قبل تغيير حالة الطلب. |
| PAY-004 | النقاط خصم محدود وليست رصيد دفع. | يحسب السيرفر `points_discount_minor = min(points_value_minor, floor(subtotal_after_eligible_promotions_minor × 5 / 100))`. تحفظ نسخة quotation، الحد، التحويل، التسوية، العكس، والأثر التدقيقي. لا تحول النقاط إلى `payment_method`. |
| PAY-005 | النقد للصيدلية هو COD أو استلام نقدي مؤهل فقط. | لا يسجل COD مدفوعاً؛ ينشئ التزام تحصيل، ثم حدث تحصيل وتسوية منفصلين. تتحقق سياسة الصيدلية ونوع التنفيذ عند الاختيار والتأكيد. |
| PAY-006 | الدفع النقدي للخدمات سياسة مزود صريحة. | تنشئ الخدمة `CASH_COMMITTED` ولا تسجل دفعاً. لا تصبح العملية `PAID` إلا بعد حدث تحصيل موثق؛ ويحدد المزود إن كان الحجز يؤكد عند الالتزام النقدي أو يحتاج قبولاً إضافياً. |
| PH-001 | طلب الصيدلية يبدأ ببث بلا دفع. | السلة والعنوان فقط يخلقان `ORDER_BROADCASTING`; لا يصدر payment intent أو total نهائي في هذه الحالة. |
| PH-002 | اختيار الصيدلية لا يساوي قبول سعر قابل للدفع عند وجود نواقص أو بدائل. | يقفل الاختيار صيدلية واحدة، ويبدأ تفاوض proposal revision إن لم يكن العرض كاملاً. لا يسمح بالدفع حتى قبول revision نهائي خادمي. |
| PH-003 | السعر النهائي snapshot خادمي. | يسترجع السيرفر توافر وتسعير المخزون عند إنشاء العرض أو revision، ويحفظ snapshot ذا version وexpiry ويعيد التحقق منه عند إنشاء الدفع. |
| PH-004 | التأمين الصيدلي قرار لكل بند. | يحفظ القرار `APPROVED` أو `REJECTED` أو `ALT_OFFERED` مع السبب والحصص والمرجع والوقت. في partial يختار المريض صراحةً covered-only أو self-pay للبنود غير المغطاة أو الإلغاء. |
| SRV-001 | الحجز الذاتي للخدمات يعتمد السعر الخادمي وحجز الموعد. | قفل الموعد مدته عشر دقائق. لا تؤكد البطاقة قبل webhook صحيح ولا تسمح بتمرير total أو slot من العميل بلا تحقق. |
| SRV-002 | التأمين للخدمات لا ينشئ دفعاً قبل قرار التغطية. | يقدم المزود قراراً خادمياً؛ يدفع المريض التحمل فقط أو يختار الدفع الذاتي أو الإلغاء بعد الرفض/الجزئية. |
| SEC-001 | حالة المجال وصلاحيات الأفعال تخرج من عقد مشترك وحارس سيرفري. | لا يوجد enum موازٍ أو transition غير معرّف. كل mutation مالي أو متعلق بالحالة أو الأسرة يحمل idempotency وowner/family validation وaudit event. |
| REL-001 | لا يدمج إلى `main` مباشرة. | تستخدم فروع صغيرة إلى `release/patient-production`، ومراجعة واحدة على الأقل، وحل المحادثات وCI أخضر قبل دمج إصدار مرشح إلى `main`. |
| REL-002 | فرع الحجر الصحي للقراءة والمقارنة فقط. | يمنع merge أو rebase أو cherry-pick شامل من `quarantine/workstation-source-51a84c7`; أي نقل يذكر المصدر والاختبار وأثره في traceability. |
