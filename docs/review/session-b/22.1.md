# 22.1 Repeat and refill: BLOCKED (needs a decision and Session S)

**Plan (CHANGED, plan amendment):** auto-refill only for items with a valid prescription; no discount on Rx refills.

**What is on `main` (checked 2026-10-18):**
- `HealthService.refillNow` throws `canonical_pharmacy_flow_required` (`backend/src/modules/health/health.service.ts`, the legacy `OrdersService.create` path is disabled because it can auto-dispatch, persist PII and orphan orders before the canonical gates).
- `prepareRefill` and the chronic reminder fields (`refill_date`, `refill_pending_order_id`, `refill_fulfilled_at`) exist; no subscription model and no reminder scheduler for refills.
- `pharmacy_ops.controller.ts` `GET orders/refills` returns `canonicalPharmacyFlowRequired()`.

**Why it is blocked:**
1. Creating a refill order is an order and payment state change. The queue gives that to Session S: `BLOCKED: needs S`.
2. The canonical refill command the disabled path points to does not exist on `main`.
3. "Order again" on past orders needs a dispensed-quantity contract from the pharmacy; the code says not to infer one.

**Questions for the owner (answer on this PR):**
- Should refill orders go through the canonical pharmacy order flow (Session S) first, and only then this item?
- For the Rx validity check, which field is the source of truth (the prescription record, not a value sent by the client)?
