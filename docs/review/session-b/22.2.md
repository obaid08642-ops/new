# 22.2 Price-drop alerts: built (back-in-stock removed)

Supersedes the BLOCKED note of commit 591f3fc9f. Owner answers (2026-10-18):

- Back-in-stock is removed entirely. Nothing was built for it on `main`, and none is added.
- A price history is stored in a new collection when the reference price changes.
- A patient is notified when the price falls by 5% or more.
- Prescription medicines are excluded.

**What is built (backend)**
- `medicine_price_history` (new collection): one row per price change `{ _id: medicine|hour, medicine_id, price, previous_price, recorded_at }`.
- `PriceAlertsService.sweep` runs hourly (`@Cron(EVERY_HOUR)`). It compares each public, non-prescription, non-controlled medicine with its last recorded price, writes a row on any change, and when the drop is 5% or more notifies every patient whose wishlist (`patient_profiles.wishlist`) holds that medicine.
- The row `_id` is medicine + hour, so two instances sweeping the same hour cannot both record the change or both notify (duplicate key → skipped).
- Notification: `NotificationType.PROMO`, route `/pharmacy/product/:id`, keys `notif.price_drop.title` / `notif.price_drop.body` (ar, en, ur in the backend dictionary).

**Not in this PR:** a patient-facing screen for the alert and the app/web wording beyond the push text. Backend dictionary carries ar/en/ur only, so hi/bn/fil users get the English text (existing backend rule).

**Open questions (answer on this PR)**
- The reference price is the last recorded price, so a drop is measured from the last sweep that saw a change. A price that rises and falls within one hour is not seen. Acceptable?
- Notifications are written per patient once per change. Should the alert be limited (for example one per medicine per day)?
