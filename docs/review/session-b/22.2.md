# 22.2 Price-drop alerts: built (back-in-stock removed)

Supersedes the BLOCKED note of commit 591f3fc9f. Owner answers (2026-10-18):

- Back-in-stock is removed entirely. Nothing was built for it on `main`, and none is added.
- A price history is stored in a new collection when the reference price changes.
- A patient is notified when the price falls by 5% or more.
- Prescription medicines are excluded.

**What is built (backend)**
- `medicine_price_reference` (new collection; not `medicine_price_history`, which is the admin price audit): one row per price change `{ _id: medicine|hour, medicine_id, price, previous_price, recorded_at }`.
- `PriceAlertsService.sweep` runs hourly (`@Cron(EVERY_HOUR)`). It compares each public, active, non-prescription, non-controlled, non-discontinued medicine with its last recorded price, writes a row on any change, and when the drop is 5% or more notifies every patient whose wishlist (`patient_profiles.wishlist`) holds that medicine. The drop is compared in piastres (no floating-point edge).
- The row `_id` is medicine + nearest clock hour, so two instances firing at the same cron moment get the same key and the second one skips (duplicate key). Indexes: `medicine_price_reference {medicine_id, recorded_at}`, `patient_profiles {wishlist.id}`.
- A sweep that runs longer than 10 minutes is abandoned, so one stuck run cannot stop alerts for good.
- Notification: `NotificationType.PROMO`, route `/pharmacy/product/:id`, keys `notif.price_drop.title` / `notif.price_drop.body` (ar, en, ur in the backend dictionary).

**Not in this PR:** a patient-facing screen for the alert and the app/web wording beyond the push text. Backend dictionary carries ar/en/ur only, so hi/bn/fil users get the English text (existing backend rule).

**Open questions (answer on this PR)**
- Reference price: a drop is measured from the previous recorded price, so a slow decline (for example 100 → 97 → 94, three steps of 3%) never alerts, although the total is 6%. Should the reference be the price when the patient added the item, or the price at the last alert?
- Delivery is at most once: the reference row is written before the holders are notified, so a failed push for one holder is logged and not retried. A retry outbox would fix that; should it be built?
- A price that rises and falls again inside one hour is not seen (the sweep is hourly).
- Push text is in the backend dictionary (ar, en, ur). hi, bn and fil users get English, as for other backend notifications.
