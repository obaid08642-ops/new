# Provider app walkthrough (2026-10-16)

Method: `docs/review/WEB_SERVICES_SESSIONS_BRIEF.md` applied to `provider-app` (doctor, pharmacy, lab, radiology, home care / nursing, hospital).
The app has no `app/**` routes: it is react-navigation (`App.tsx` plus one navigator per provider type), so "every screen" means every
screen registered by the six navigators (`docs/review/inventory/screens.json`).

How it was run
- `expo export --platform web` with `NABD_WEB_TEST=1 EXPO_PUBLIC_NABD_E2E=1` (browser test build; the QR-code package is not installed in this checkout, so the export aliases it to a stub; nothing of that is committed), served with an SPA fallback, pointed at the local live stack on a fresh test DB.
- One provider of each type registered through the real onboarding endpoints and approved by the admin (`tools/live/j_onboarding.py`), then the type's journey was run so every dashboard has data (orders, bookings, allocations, wallet entries): `j_pharmacy`, `j_lab`, `j_radiology`, `j_nursing`, `j_consultation`, `j_facility`.
- Each provider signed in through the app's own Welcome and Login screens in Chromium at 390x844.
- Crawl: the existing tap crawler (`tools/live/rn_nav_crawl2.py`, copied and bounded to 13 minutes per type) tapped the controls of the screens it reached and checked, per write, that the typed value reached the database. Evidence: `docs/review/evidence/rn_walk_provider-app_<type>_2026-10-16.json`.
- Visit: every registered route of each type was opened directly by route name in Arabic and in English (`rn_visit_provider-app_<type>_2026-10-16.json`): JS errors, 4xx/5xx reads, raw keys, icon words, Arabic in English, Latin text in Arabic, "undefined/NaN", horizontal overflow.
- Static pass: every `client.get/post/put/patch/delete` call of the app (374) matched to a backend route by method and path (0 unmatched), every write handler read for "answers ok and stores nothing", and the money, order and prescription flows read end to end against the backend service.
- The provider app has two languages (ar, en) and writes its strings inline as `AR ? 'عربي' : 'English'`; there is no translation file to hold raw keys, so "missing translation" here means a string that has only one language.

## Counts
- Provider types walked: 6 (doctor, pharmacy, lab, radiology, home care, hospital), one approved provider each, signed in through the app's own screens.
- Screens: 193 registered screens opened directly by route name, each in Arabic and in English (386 openings: doctor 37, home care 37, hospital 46, lab 31, pharmacy 35, radiology 7); 146 screen states reached by tapping (98 distinct screens); the rest of the registered names are not mounted by their navigator (`sos_dispatch`, `gps_router`, `ambulance_fleet`, `hospital_dispatch`, `delivery_track`, `pharmacy_info`, `checkin`, `visit_report`: dead names in the inventory, nothing navigates to them).
- Controls: 1,083 tapped (372 changed the screen, 231 navigated, 26 wrote to the backend, 409 had no visible effect, 28 not found by the crawler, 11 skipped as destructive, 6 JS errors). The "no visible effect" bucket is mostly selection chips, inputs and tabs that restyle only; it was read by hand and the real ones are in the table.
- Writes: 26 writes were made by the crawl and checked against the database; every typed value that was sent was stored except the ones the server refused (503 on `analyze-file` is the missing AI provider on the test stack). Persistence of the other writes (availability, working hours, profile, allocations) answered 2xx.
- Static: 374 API calls of the app matched to backend routes (0 unmatched; 2 land on handlers that always answer 503: `POST /nursing/visits/:id/respond`, no longer used, and `GET /pharmacy/orders/refills`, P14), write handlers read for "answers ok and stores nothing" (found in the walkthrough of the patient app: none here), money, order and prescription flows read end to end.
- Defects: 35 (wrong 14, broken 11, copy 7, illogical 3); 27 fixed in 4 PRs (1628 money and shared components, 1629 session and network, 1630 chat, 1631 order screens), 8 open. 4xx and 5xx seen during the walk: `404 GET /provider/profile/image/status` (P23), `503 POST /pharmacy/procurement/analyze-file` (no AI provider configured on the test stack), `503 GET /pharmacy/orders/refills` (P14), `400 POST /chats/threads/booking` and `/nursing/notes` when a screen was opened without its order (parameterless direct open), and `404 GET /storage/<id>/signed-url` for the placeholder clinic image id the onboarding journey stores. No other 4xx or 5xx.
- Seeded data: the journeys' own data (orders, bookings, allocations, wallet entries, one ledger clawback added for the check).

## Not reachable on react-native-web (needs a device)
- Camera and gallery: lab sample scanner, QR check-in (facility), prescription photos, shelf photo for procurement, profile photo capture, ID and licence documents in registration.
- Push notifications (token registration, deep links from a notification).
- Calls: LiveKit video and voice (`VideoCallRoom`, live consultation, waiting room).
- Maps and GPS: `react-native-maps` is native-only; on web the two screens that load it directly throw `codegenNativeComponent is not a function` (Location tab of the profile editor, doctor Settings > "Location and coverage"). Not a device defect.
- Biometric login, haptics, vibration, file save and share sheets, secure storage (shimmed in the test build).
- Token expiry: the access token lives 14 days (`provider.module.ts:136`), so the 401 path was not exercised end to end.

## Remaining (not fixed in this session)
- Product decisions: P14 (a refill queue for pharmacies, or remove the menu entry; the screen is honest now) and P20 (nursing working hours: wire shifts, max daily visits and emergency-ready to dispatch, or drop the screen).
- P21 revenue insights need a server-side revenue aggregate (the stats fix in PR 1628 already makes `statsPeriod` correct; the screen can move onto it). P22 doctor price save files two approval requests.
- Copy debt of a two-language app that writes strings inline (`AR ? ... : ...`, no translation file, so no gate covers it): P27, P28; layout: P30; the "read failure looks like an empty list" pattern in the other lists (P31).
- Needs a device: camera and gallery, push, calls, maps and GPS, biometric login, token expiry (14 days).
