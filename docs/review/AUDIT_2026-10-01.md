## 2. Methods used in this round (new tools, all in the repo)

| Tool | What it proves |
|---|---|
| `tools/audit/ui_inventory.js` | Every screen's interactive elements and API calls, from the AST |
| `tools/audit/route_dto.py` | Backend write route → DTO → fields, resolved through the controller's own imports |
| `tools/audit/typecheck_contracts.py` | Per field, the **type** the screen sends vs the type the DTO declares. Also keys the DTO does not declare (the server runs `forbidNonWhitelisted`, so those are a 400). Static: every hit is confirmed live before being reported |
| `tools/live/form_trace.py` | All 726 write call sites replayed as the right actor, with the screen's payload keys and a unique value per field, then checked: accepted? each value stored in Mongo? shown back by the same screen's reads? |
| `tools/live/field_trace.py` (round 3) | Provider registration, field by field, up to the admin's screen |
| `tools/live/ui_form_fill.py` | Real browser: opens each admin/website form, fills every visible field, presses save, then checks the request and the database |
| `tools/live/rn_web_crawl.py` | Real browser on the **native app exported to web**: opens every route, fills inputs, taps every element, and classifies the result as WRITE / NAVIGATE / UI_CHANGE / NO_EFFECT / JS_ERROR |
| `tools/live/rn_nav_crawl.py` | The same for the **provider app**, which has no URL routes (React Navigation). It signs in through the real Welcome → Login screens, then walks screens by tapping from each provider type's dashboard and replays the tap path to re-enter each one |
| `tools/audit/nocheck_tsc.py` | Type-checks an app with every `@ts-nocheck` removed (temporary copy). Fails on runtime-fatal errors (undefined names, missing exports, use before declaration) |
| `tools/live/admin_buttons.py`, `gate_ids.py`, journeys | From earlier rounds (reused, see §4) |

**Limits of the crawlers (read before trusting a status).**
- NO_EFFECT means no change in text, URL or requests. A control whose only effect is a style (a selected segment, a highlighted chip) is reported NO_EFFECT. Those need a visual check, and none is reported as a defect on that basis alone.
- The first runs counted only `tabindex=0` elements and missed controls rendered as `<button>`/`role=button` and icon-only controls. The v2 runs (`*_v2_*`) include them.
- Logout, account deletion and SOS/emergency requests are answered locally by the harness (never sent), and the element is reported BLOCKED_DESTRUCTIVE.
- The provider app's connectivity probe to `https://1.1.1.1` is answered by the harness (see R38).

**How mobile results are labelled.** They are **react-native-web in Chromium**, never "device".
- A test-only Metro alias (`NABD_WEB_TEST=1`, `tools/live/rnweb/secure-store-web.js`) keeps the session in localStorage, because `expo-secure-store` has no web implementation.
- Store builds are unaffected.
