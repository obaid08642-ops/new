# Client journey matrix: patient app and patient web (Phase 1, item 3, read-only)

Scope: the four client codebases (patient-app, patient-web, provider-app, admin). This file follows one patient from opening the app to support, and says for each step which screens carry the step in the app and on the web, what is Saudi in the client code (file:line), and what must become market-driven. It adds the **client side** to `journeys.md` (B, backend routes). Evidence for every row is a `file:line` read in this pass; the full hit lists are in `ui-evidence.md`. No code was changed.

How to read: **SA today** = what the client does now. **EG** (or any second market) differences are the same **[unverified]** research assumptions as in `journeys.md`; this file does not repeat them, it only says what the client has to take from the server instead of from a constant. "Flow unchanged" means the journey (pharmacy broadcast + offers, booking, payment, receipt) keeps its screens and order; only inputs, formats, lists and texts change.

## Finding that frames everything

No client has the idea of a market. A search for `market`, `marketId`, `country_code`, `countryCode`, `MarketContext` over the four source trees (tests, `node_modules`, locale catalogues excluded) finds **0 files** in patient-app, patient-web, provider-app and admin. Saudi Arabia is not a configuration value in the clients: it is spread over constants, regexes, formatters and literals (see `ui-impact.md`). The one config object that looks like a seam is `patient-app/src/core/config/ConfigManager.ts:224-225` (`defaultCurrency: 'SAR'`, `defaultPhoneCode: '+966'`), and it is a local constant, not something read from the server.
