# Ordering M0 boards: flowa (spec section 6 items 1-5)

Each board holds app light 390, app dark 390 and web light 1280 side by side, with extra stacked state frames. Sample names, areas, prices and test names are backend data (catalogue, providers); they are in the strings file only so the six languages can be checked.

| Board | Spec 6 | Purpose | App route | Web route | Backend field / endpoint | States shown |
|---|---|---|---|---|---|---|
| `Ord01-ContextBar.dc.html` | 1 | Context bar (place, payer, for whom) and its bottom sheet; new-patient first ask with skip | new: shared component on every service screen, sheet as modal | new: shared bar under the web nav, popover and dialog | profile default address, saved insurance (company + class), family members; needs-backend: one `GET /me/ordering-context` (or the three existing reads) and a PATCH to save the choice | complete, sheet open, new patient + skip, nothing saved, loading, error + retry, go-yourself + cash + family member |
| `Ord02-ServiceHome.dc.html` | 2 | Service home for lab, radiology, nursing: search, order entry (my orders / photo), packages, most requested, "from X SAR", browse labs as secondary path | new: `/labs`, `/radiology`, `/nursing` service homes (replace ServiceHub entry) | new: `/[locale]/labs`, `/radiology`, `/nursing` | needs-backend: catalogue items with prep, turnaround, `facilityOnly`, `portable`, `requiresOrder`; area-cached "from" price + provider count for the context; packages | lab, radiology (facility-only labels), nursing (gender pref, series hint), empty search + alternatives, loading |
