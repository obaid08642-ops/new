> Generated by `node tools/design/screen-inventory.mjs` at commit `5cf8f754`. Do not edit by hand: re-run the script after routes or API calls change (`--check` fails when this file is stale).
> Source of truth for the rebuild order: `DESIGN_HANDOFF_FINAL.md` §4. Progress per batch lives in `PROGRESS.md`; endpoint health in `WIRING_REPORT.md`.

**Columns**
- **Template**: hub, list, detail, form, flow step, tracking, result, settings, state (from the route name; correct it in `template()` if wrong). `redirect` = the route only forwards to another one (target in the API column); it needs no design.
- **Board**: closest board in `canvas/` (web uses `ProductWeb`, `HomeWeb`, `SearchWeb`, `AuthWeb` where they exist). `none: <kind>` = no board is close; listed under design gaps in `PROGRESS.md`.
- **Batch**: rebuild order from §4 (0 = core screens whose boards already exist; 13 = web-only pages).
- **API**: endpoints the screen reaches through its own code and the symbols it imports (`METHOD /path`, `:param` = dynamic). `web→` = BFF route in `patient-web/app/api`, `proxy→` = `/api/patient/*` proxy. Full list per route in `inventory/screens.json`.
- **Status**: rebuild state from `docs/design/screen-status.json` (`"<app> <route>": "in progress" | "done (#PR)"`). `—` = not started. Every rebuild PR updates that file, re-runs this script and updates `PROGRESS.md`.
