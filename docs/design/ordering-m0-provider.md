# M0 boards: medical orders and provider declaration (agent "provider")

Frames per board: app light 390, app dark 390, web light 1280 (provider boards use provider-app web, `expo start --web`). **Ord22 is mobile only (390 light + dark)**, a doctor-side screen of the provider-app. Each board also carries the states (loading, error, empty, expired, sent/done) as compact stacked frames. Provider-app strings need ar + en; all six languages are in `ordering-m0-strings.provider.json`. Board positions: `canvas/ordering-m0.provider.boards.json` (x=2400, to sit beside the other agent's column).

Notes
- Principles shown: context bar (Ord20, Ord21, Ord33 preview), "from X SAR" and "estimated" share (Ord20, Ord33), clocks on waits (approval countdown with what happens next, Ord20).
- Colours only from `tokens.json` (check: 30 hex values, 0 outside the token file; the only rgba values are token borders/scrims and the board shadows). Icons are FIcon; logo is the Noon Dot header of ProductWeb.
- Open: how many validity options a doctor may choose (30/90 days/6 months shown; spec says only "validity").
- Open: whether medicines inside the structured order replace or link to the existing e-prescription (the composer shows them as a group).
- Open: the number of wizard steps (6 spec items grouped into 4 steps).
- Open: completeness weights are illustrative (+15/+10/+5); real weights are a backend decision.
