# Runtime check, Batch 1 (patient-web)

Generated by `node tools/design/runtime-check.mjs` against http://localhost:3120 (locale `ar`, 390 px) talking to a seeded backend.
Scenarios: **normal** = real responses; **empty** = every data GET answered `200 []`; **error** = every data GET answered `500`. Injected by `tools/design/fault-proxy.mjs` between patient-web and the backend, so server-rendered fetches are covered too.
Server-rendered fetches are not visible to the browser, so for the normal scenario the backend's HTTP log is read as well (listed as "Server" below).

**Batch 1b (patient-web), production webpack build of `wip-b1b-web` on port 3120, fault proxy on 3121 (`--only` the slice's static routes, `--extra` for the routes that need a query or an id).** 30 runs, 2 flagged, both expected: a prescription id that does not exist makes the backend answer `GET /prescriptions/:id` 404, and that is the page's real not-found state (the tool counts any non-2xx backend call as a failure). Every other run: 0 console errors, 0 page errors, 0 CSP violations. A first run of this build had a CSP violation on five routes (zod, reached through a shared client module, probes for `eval`); fixed and pinned by `tests/pharmacy-rx.test.tsx` ("never reach zod"). Error scenario: the screens show the board's error state with retry (`runtime/batch-1-web/*-error.png`; `/prescriptions`, `/cart/prescription` looked at). The routes with a patient session need the seeded patient `+966509999999`; the seeded patient has no prescription, no saved address and an empty server cart, so the normal runs show the real empty states. Data-bound layouts were looked at through a TEST-data proxy kept outside the repo (screenshots `-testdata`).

**DOM check** (Playwright against the same build, 29 scenarios x 390 / 768 / 1440 x light / dark, Arabic: 174 runs): 0 `style=` attributes (the framework's own `next-route-announcer` excluded; the server HTML has none), 0 horizontal overflow, 0 console errors, 0 controls without an accessible name. Targets under 44 px that remain belong to the shell of 1a (top-bar brand, language and theme buttons, account and sign-out icons) and to the global not-found page's footer links, none to this slice (the address "Change" link and the cart's product links were 41x44 and 22 px tall and are fixed). The same check on the old build (`origin/design/batch-1`, port 3124): 48 of its 60 runs had inline-style attributes and CSP violations.
