## Needs review

| Route | Element | Kind | Note |
|---|---|---|---|
| `/nursing/visits` | Visit card opens live-tracking with type=patient | client | type=patient makes the tracking page say 'go and pick up the nurse' for every home visit opened from the list; the booking flow sends type=nurse. Left as is (logic). |
| `/nursing/nurse-profile` | Transport choice | client | The choice is not part of the POST /nursing/bookings payload; it only changes the tracking wording. The invented '(0 SAR)' price on the second option was removed. |
| `/nursing/nurse-profile` | Booking time | backend | The booking is built from a fixed list of daily slots (08:00 to 13:00), not from the nurse's availability. |
| `/nursing/service-details` | Injection policy check | client | Decided by service ids and Arabic words in the title; a title in another language skips the prescription dialog. |
| `/nursing/service-details` | Providers query | client | The search, gender and nationality values are put in the URL without encoding. |
| `/nursing` | Search and filters | backend | Only passed to /home-care/providers on the next screen; the hub itself filters nothing. |
| `/nursing/live-tracking` | Back button | owner | Goes back or to the home tab; the old screen always went to the home tab. Kept the old target as the fallback. |
| `/nursing/live-tracking` | Visit steps | backend | The tracking answer has no steps, so the OrderTracking timeline is not drawn. |
