# Batch 0 fixes (design/batch-0-fixes): element audit of what the PR touches

Same rules as Batch 0 (`QUALITY_STANDARDS.md` §7). The full element audits of the screens are `batch-0-web.md` and `batch-0-app.md`; this file lists the elements whose source or target changed in this PR, plus the shared pieces that moved. Format: element, source (API field / user input / static copy), goes to.

## B2: silent guest session (patient-app)

| Screen / element | Source | Goes to |
|---|---|---|
| `/` splash: logo | static (`NabdLogo`) | none |
| `/` splash: "نبض بلس" and the tagline | static copy | none |
| `/` splash: session check | SecureStore `STORAGE_KEYS.AUTH_TOKEN` (`src/utils/guestSession.ts`) | when a token is stored, nothing |
| `/` splash: silent guest request, started on mount so it runs while the logo plays (never delays the splash; the splash waits at most 3 s for it) | device id from AsyncStorage `@nabdah_device_id` (`getDeviceId`) | `POST /auth/guest` with header `x-device-id` (`auth.controller.ts:177`), then `storeAuthSession` (SecureStore) and `guestLogin` in the auth slice |
| `/` splash: navigation | none | `router.replace("/(tabs)")`; on an exception `/(auth)/welcome` (unchanged) |
| `/(auth)/welcome`: "المتابعة كضيف" | user press | the same `createGuestSession()` (one helper for the button and the splash), then `router.replace('/(tabs)')`; failure message is static copy |

Effect: the seven Home calls that need a JWT (`/health/reminders`, `/health/vitals/summary`, `/home/upcoming-appointment`, `/maternity/profile`, `/mental-health/mood`, `/nutrition/daily-summary`, `/users/me/profile`), `/home/search` and `/notifications` answer 200 with a guest token (`audit/runtime-batch-0-app.md`, column "Guest") instead of 401, so the Home warning banner does not appear on first launch. `_layout.tsx` still never creates a guest (`authGuestPolicy.test.ts`).

## B5: web `/register` and `/services`

| Element | Source | Goes to |
|---|---|---|
| `/register`: session probe on load | none (cookie) | `GET /api/auth/session` (BFF) → `GET /auth/me` (upstream, only with a cookie). With no session or an expired one it now answers `200 {authenticated:false}` instead of 401, so the console stays clean; an upstream outage still passes its status. Used only to show the guest-conversion state (`isGuest`). |
| `/register`: name, email or phone, password, consent box, submit | user input | `POST /api/auth/register` (unchanged) |
| `/services` | none | `next.config.ts` redirect to `/:locale` (Home, which is the services grid). It used to land on `/consultations/doctors`, whose inline styles the CSP blocks. `app/[locale]/services/page.tsx` redirects the same way. |

## Search results (web `/search`)

|---|---|---|
| results list rows | `GET /api/patient/home/search?q=` fields `id`, `type`, `typeEn`, `name`, `nameEn`, `sub`, `subEn`, `rate`, `price` | row links as in `batch-0-web.md` |

## Colours (app)

`ScreenStates` (retry button and label), `OfflineBanner` (offline and back-online banner, text), `SearchBar` (active filter icon) and `Progress` (active step label) used raw `#fff`, `#F0567A`, `#2BB89C`. They now read `c.action.primary.bg`, `c.text.onBrand`, `c.status.danger.*` and `c.status.success.*` from the tokens of the active theme. These four components have no board render of their own; verified by the app tests and the type check.
