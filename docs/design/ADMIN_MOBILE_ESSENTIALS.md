Evidence is in `ADMIN_WIRING_REPORT.md`, `docs/journeys/admin.md` and `docs/design/needs-review/admin-journeys.json`. Status words: **exists** (UI and backend work), **backend gap**, **missing UI**, combinations when both._

## Other mobile-relevant gaps

- Provider approval on a phone: approve is three `window.prompt` dialogs; reject, request-changes and bank approval have no UI; the Suspend button used as reject fails on pending providers (journey 1).
- Refunds: three screens and a queue that approves without paying; the maker-checker approvals list and execute route have no screen (journey 3).
- Role guards: 28 sensitive writes are role-only on the backend (no permission), 28 page/route permission mismatches, one nav permission (`users.view`) that does not exist, so the global search link is hidden from every admin. Details in `ADMIN_WIRING_REPORT.md` section "Role-guard findings".
- Eleven pages have no nav link (`dashboard`, `notification-center`, `commissions`, `shortage-reports`, `image-suggestions`, `legal-policies`, `ai-control`, `health-dashboard`, `analytics`, `theme-control`, `order-detail`).

## Public directory pages that live inside admin

The admin app (`admin/src/pages`) also serves the public site: `/` (landing), `/doctors`, `/medicines`, `/facilities`, `/lab-services`, `/home-care-services`, `/articles`, `/s/[type]/[slug]` (SEO entity pages) and the shared component `components/PublicDirectory.tsx`. They are outside `/admin`, so `proxy.ts` (login is forced only for paths starting `/admin`) does not guard them: they are public by construction, served by the admin deployment.

Findings:

- All six directory list pages call `fetchDirectory('/care/doctors?limit=300')`-style relative URLs from `getServerSideProps`. Node `fetch` rejects a relative URL and the `catch` returns `[]`, so on the server these pages render empty lists (status BAD_URL in the audit). The endpoints themselves exist and are `@Public`.
- `/s/[type]/[slug]` calls the backend directly with `${API_BASE}/api/v1/seo/meta/...` (works, public route).
- Owner/reviewer question: should public pages be part of `patient-web` instead? They duplicate patient-web's job (doctors, medicines, articles) and put public traffic and its CSP on the admin host, whose gate is meant for admins only.
